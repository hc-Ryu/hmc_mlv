# uni_section_v18 — 17-Section B-Pillar 초기 좌표 구성

출처: `uni-section/code/uni_section_v18.py`의 `build_bpillar_section()` (5-part hat 단면, 1개 섹션).
이 문서는 그 단일 섹션을 **17층 B-pillar**로 확장하는 좌표 구성 방법과, 층별 면적/초기 전소성 모멘트(Mp)
검증 결과를 기록한다.

## 0. Synod design 세션 요지

`/synod design` 세션(conf: Gemini 95 vs OpenAI 74, 쟁점 있음)에서 Gemini는 "y축 단독 스케일링"을,
OpenAI는 "y축 단독 스케일링은 PNA(소성 중립축) 이동으로 인해 면적이 늘어도 Mp가 줄어드는 구간이
생길 수 있다"며 등방(x,y) 스케일링과 **수치 검증 필수**를 주장했다.

이 쟁점을 실제 `compute_edge_mp_pna()` 로직으로 재현해 s=1.00→1.60 구간을 17단계로 스윕한 결과,
**y축 단독/등방 스케일링 모두 이 특정 형상에서는 area·Mp가 완전히 단조증가**했다(OpenAI가 우려한
역전은 이 프로파일에서는 실측상 발생하지 않음 — Critic 결과, 두 방식 모두 기술적으로는 유효).

다만 사용자 요구사항("단면의 전체적인 형상... 모든 섹션이 같도록")을 **글자 그대로**(진짜 닮음 변환)
만족시키기 위해 **등방(x,y) 스케일링**을 채택한다. y만 늘리면 hat의 가로세로 비율이 섹션마다 달라져
엄밀히는 "같은 형상"이 아니게 되기 때문이다.

## 1. 스케일링 파라미터화

섹션 인덱스 `k = 1..17` (사용자 표기: 1번째=가장 아래, 17번째=가장 위).

```
s(k) = 1.6 - 0.6 * (k - 1) / 16      # k=17 -> s=1.0 (원본, 최상단), k=1 -> s=1.6 (최하단)
x_k(i) = x_base(i) * s(k)
y_k(i) = y_base(i) * s(k)
```

- `x_base(i)`, `y_base(i)` : `build_bpillar_section()`이 만드는 원본(section 17) 좌표 그대로
  (part 0/2는 `_hat_profile()` 트라페조이드, part 1/3/4는 기존 상수/트림 로직 그대로).
- **두께(t)와 항복강도(fy)는 파트에만 의존하고 섹션에는 의존하지 않음** — `part_configs`의
  `t_val`, `fy_val`을 17개 섹션 모두 동일하게 사용 (요구사항 4 충족).
- `s_max = 1.6`: 최하단이 최상단 대비 60% 확대. 실제 B-pillar가 하부(rocker 접합부)로 갈수록
  단면이 커지는 정도를 반영한 값(Gemini 제안 유지).
- 선형 보간(`α=1.0`): 가장 단순하며 전 구간에서 단조성이 실측으로 확인됨(아래 §2).

## 3. 파트 구성 (모든 섹션 공통, uni_section_v18.py 그대로)

| part_id | 이름 | flange_y(base) | crown_y(base) | t (mm, 전 섹션 공통) | fy (MPa, 전 섹션 공통) | x_ratio 트림 범위 |
|---|---|---|---|---|---|---|
| 0 | Outer Hat | 30.0 | 65.0 | 2.30 | 1470.0 | 전체 (0~1) |
| 1 | Inner Plate | 28.05 / 8.05 / 15.0 (구간별 상수) | - | 1.60 | 980.0 | 전체 (0~1) |
| 2 | Inner Hat | 9.65 | 45.0 | 1.60 | 1470.0 | [0.2, 0.8] |
| 3 | Patch 1 | 9.55 / 16.5 (구간별 상수) | - | 1.40 | 980.0 | [0.3, 0.7] |
| 4 | Patch 2 | 7.45 (상수) | - | 1.60 | 440.0 | [0.7, 0.8] |

- Part 0 crown(65.0) > Part 2 crown(45.0) 관계는 등방 스케일링(양쪽에 동일 `s(k)` 곱)이므로 모든
  섹션에서 그대로 보존됨 → 기존 collision loss가 가정하는 outer-hat > inner-hat 비관통 순서 유지.
- x_ratio 트림 범위(part 2/3/4)는 스케일과 무관하게 **비율** 기준이라 섹션이 바뀌어도 동일 비율
  구간을 유지 (전체 폭이 `160*s(k)`로 커져도 트림 비율은 불변 → part 4가 outer hat lip을 벗어나지 않음).

## 4. 학습 루프 통합 관련 참고 (범위 밖, 기록만)

이번 작업은 좌표 구성 + 시각화까지가 범위이며, `uni_section_v18.py`의 `train_step()`/`CGDN`은
여전히 단일 섹션(`section_id=0.0`) 가정으로 동작한다. 17-섹션 학습 통합(AI_design_v0.py처럼
섹션별 loss 평균 또는 3D 그래프 연결)은 별도 command 문서가 필요한 범위 밖 작업으로 남겨둔다.
