## 문제 1: Inner가 Plate를 기하학적으로 관통

### 근본 원인 (review_v1_3.md에서 확정, 신뢰도 95%)

두 가지가 결합되어야 발생한다.

- **(a) 상시 활성 면적 하강압**: `usv18.compute_alda_loss()`의 `f = area/target_area`는 relu 게이트가
  없는 **선형 항**이라, 5% 감량 목표를 이미 달성한 뒤에도 계속 면적을 밀어낸다. `l_mass`(예산 제약,
  목표 초과분만 벌점)가 0이 되어도 `f`는 멈추지 않는다. Stage4에서 area가 목표 밑인데도 8.5% 더
  줄었고, Plate가 `T_MIN=0.7mm`에 완전히 포화됐다.
- **(b) 정적·클램프된 충돌 손실**: `uni_section_v18.build_collision_spec()`(불변 대상)은 **학습
  시작 전 초기 형상 1회**로 `clearance`/`sigma`를 고정한다. `compute_collision_loss_v5()`의
  위반량은 `.clamp(max=1.0)`으로 **1mm 이상 관통 시 그래디언트가 정확히 0**이 된다. (a)가 만든
  압력을 (b)가 막지 못하면서 실제 관통이 일어났다.

### 순위별 아이디어

#### [1순위, 실현가능성 High] 보조 무클램프 충돌 페널티 추가
기존 `collision_spec`(불변 함수 `build_collision_spec()`의 반환값)을 재사용하되, `AI_design_v1_4.py`
안에서 **클램프 없는** 이차 페널티를 별도로 계산해 원본 충돌 손실 위에 **추가**한다(대체가 아니라
보강).

```python
# AI_design_v1_4.py 신규 함수 — collision_spec은 재사용, 클램프만 없앤다
def compute_collision_penalty_unclamped(new_coords, t_final, part_ids, section_ids,
                                         collision_spec, penetration_floor=0.8):
    """violation = relu(-gap - penetration_floor)  → 1mm 클램프 없이 관통 깊이에 비례해 계속 커짐"""
    ...
```

Gemini는 `penetration_floor≈0.8mm`부터 발동하는 이차 페널티를 제안했다 — 원본 손실이 아직 유효한
얕은 침투 구간(0~0.8mm)은 원본에 맡기고, 원본이 죽는 구간(1mm 근방)부터 이 보조 항이 인계받는
설계다. 두 손실이 겹치는 0.8~1.0mm 구간은 이중 페널티가 되지만 방향이 같으므로 문제없다.

**장점**: `uni_section_v18.py` 무수정, 계산 비용 낮음, 그래디언트 연속성을 구조적으로 보장.
**단점**: 신규 하이퍼파라미터(`penetration_floor`, 가중치) 튜닝 필요.

#### [2순위, 실현가능성 High] Stage 4 진입 시점에 collision_spec 재계산
`uni_section_v18.build_collision_spec()`을 3단계 종료 시점의 **현재** `new_coords`/`t_final`로
한 번 더 호출해 `clearance`/`sigma`를 얇아진 형상 기준으로 갱신한다. 기존 함수를 그대로 재사용하는
가장 저비용 조치.

**장점**: 코드 재사용, 구현 5줄 내외.
**단점**: 갱신 시점(Stage4 경계) 이전의 얕아진 형상에서는 여전히 구형 clearance를 쓴다 — 1순위와
병행이 권장됨. Gemini는 "손실값이 Stage4 경계에서 불연속으로 튈 수 있다"는 트레이드오프도 지적했다.

#### [3순위, 실현가능성 High] 면적 하한(soft-floor) 가드레일 추가
`f`의 상시 하강압을 상쇄하기 위해, 목표의 90~92% 밑으로 내려가면 **반대 방향** 벌점을 추가한다.

```python
l_area_floor = torch.relu(1.0 - area / (SAFETY_RATIO * target_area)) ** 2   # SAFETY_RATIO ≈ 0.90~0.92
```

**장점**: `f`의 근본 특성(하한 없는 선형항)을 직접 겨냥, 개념적으로 가장 명확.
**단점**: 목표 구간이 사실상 밴드(`[0.90·target, target]`)가 되어 §2.6의 "초과분만 벌점" 철학과
살짝 충돌 — §2.6.6 완화 사다리 문서에 밴드 도입 사실을 명시해야 함.

## 문제 2: 34개 게이트 중 0개 삭제

### 근본 원인 (review_v1_3.md에서 확정, 신뢰도 97%, 두 모델 독립적으로 동일 수식 유도)

엔트로피 손실 `entropy(z) = -[z·log(z)+(1-z)·log(1-z)]`은 **대칭 함수**이며 그래디언트
`∂L_ent/∂z ∝ logit(z)`는 z가 이미 있는 쪽(0 또는 1)을 강화한다 — "삭제 유도"가 아니라 "현재 위치
강화" 항이다. `init_log_alpha=2.0`(z≈0.986, 존재 쪽)에서 시작하고, v1.3이 질량 역설을 고치려
`w_sparse=0.0`으로 만들면서 위치 무관하게 0쪽으로 미는 유일한 힘이 사라졌다. 남은 면적 신호(`f`의
게이트 성분)는 엔트로피보다 약 20배 약하다.

### 순위별 아이디어

#### [1순위, 실현가능성 High] 중립 초기화 + 지연·어닐링 엔트로피 (결합안)
Gemini가 별개로 논의된 두 아이디어(중립 초기화, 엔트로피 지연)를 하나의 3단계 스케줄로 결합해
제안했다 — 이 문서의 최고 순위 추천안이다.

1. `init_log_alpha: 2.0 → 0.0` — 모든 게이트가 `z≈0.5`(엔트로피의 불안정 안장점)에서 출발.
2. Stage 1~2 동안 `alpha_ent=0.0` 고정 — 이 구간은 순수하게 물리/면적 신호만으로 게이트가
   유의미한 방향으로 움직일 시간을 번다(약한 신호라도 방해자가 없으면 누적된다).
3. Stage 3 진입 시점부터 `alpha_ent`를 `0.0 → 0.1`(또는 §1의 `ALPHA_ENT_V13=0.05`)까지 **점진적으로
   어닐링** — 이미 물리가 결정해 놓은 방향으로 게이트를 이진화(확정)만 시키는 역할로 전환.

**장점**: "임의 페널티 없음"이라는 v1.3 철학을 유지하면서 엔트로피의 역할을 원래 의도(이진화 확정)로
되돌린다. 조기 고착(premature lock-in)을 구조적으로 방지.
**단점**: 하이퍼파라미터 3개(초기화값, 지연 시점, 어닐링 곡선)가 새로 생겨 튜닝 공간이 넓어진다.

#### [2순위, 실현가능성 High] 지연만 단독 적용 (중립 초기화 없이)
1순위의 부분집합. `init_log_alpha=2.0`은 그대로 두고 `alpha_ent`만 `ASWC_STAGE2_END`(400) 이후로
지연시킨다. 사용자와의 사전 논의에서 나온 안. 변경 범위가 가장 작다(`AI_design_v1_3.py`에서
`alpha_ent`가 이미 `train_step_multi()` 인자로 분리되어 있으므로 호출부 한 줄만 epoch 조건부로
바꾸면 됨).
**장점**: 최소 침습, 기존 초기화(설계 초기값에 가까운 "전부 존재" 프라이어)를 유지.
**단점**: `z≈0.957`에서 출발하므로 1순위보다 약한 신호로 더 오래 버텨야 한다 — 지연 구간을 충분히
길게 잡아야 효과가 있다.

#### [3순위, 실현가능성 Medium] 면적 가중 `w_sparse` 재도입
command_v1_3.md §2.2가 이미 스펙만 정의하고 미사용 상태로 남겨둔 `USE_AREA_WEIGHTED_SPARSE` 스위치와
`_per_candidate_area()` 헬퍼를 활성화해, `w_sparse=0.02~0.05`를 **면적 가중**(패치 실제 면적
기여도에 비례)으로 재도입한다. 옛 v1.2의 "상수 페널티"(질량 역설의 원인)와 달리 위치·면적 무관하지
않으므로 재발 위험이 낮다.
**장점**: command_v1_3.md에 이미 설계돼 있어 스펙 추가 작업이 거의 없음(구현만 하면 됨).
**단점**: 튜닝 실패 시 §2.2가 경고한 "침묵 no-op"(스위치 켜고 가중치 0으로 두면 아무 효과 없음)
재발 위험 — §1의 assert 가드가 이미 이를 방지하도록 되어 있어 상대적으로 안전.

#### [4순위, 실현가능성 High] 삭제-부재 감시 규칙 (R4) 추가
§7의 R1~R3은 전부 "사망(deletion) 이벤트"를 트리거로 삼기 때문에, **애초에 사망이 한 건도 없는**
이번 실패 모드를 감지하지 못한다. `ASWC_STAGE2_END` 이후 N epoch(예: 200) 동안 어떤 게이트도
0.5 밑으로 내려가지 않으면 경고를 출력하는 R4를 추가한다. 이 자체는 문제를 "고치지" 않고 "조기
발견"만 하므로 다른 아이디어와 항상 함께 적용한다.
**장점**: 구현 매우 간단, 다른 조치들의 효과를 검증하는 계측기 역할도 겸함.
**단점**: 근본 해결책이 아님 — 반드시 1~3순위 중 하나 이상과 결합.

## 두 문제의 상호작용 (Gemini 단독 제시, Claude 교차검증)

1. **초기화가 낮추는 초기 충돌 위험**: `init_log_alpha`를 0.0으로 낮추면 게이트가 `z≈0.5`에서
   시작 — 패치의 유효 두께(`t_final = t_raw·z_gate`)가 처음부터 절반 수준이라 초기 단면적이 작다.
   이는 문제 2의 해법이 문제 1의 충돌 위험을 **초기에 완화**하는 부수 효과를 낳는다(초반부터 두꺼운
   전체 구조가 급격히 얇아지는 상황 자체가 줄어듦).
2. **경쟁 관계로 인한 자기 규제**: 문제 1의 1순위(무클램프 충돌 페널티)와 문제 2의 3순위(면적 가중
   `w_sparse`)를 함께 적용하면, "면적을 줄이려는 삭제 압력"과 "형상이 겹치지 못하게 막는 충돌
   페널티"가 서로를 견제해 — **기하학적으로 성립하는 삭제만 실제로 일어나는** 건강한 균형이 생긴다
   (Gemini 표현: "healthy competitive dynamic").
3. **권장 조합**: 문제1 1순위(무클램프 충돌) + 문제1 3순위(면적 하한) + 문제2 1순위(중립초기화+지연
   엔트로피) + 문제2 4순위(R4 감시)를 최소 조합으로 권장한다. 문제1 2순위(collision_spec 재계산)와
   문제2 3순위(면적가중 w_sparse)는 여유가 있으면 추가하는 2차 조치로 분류한다.
