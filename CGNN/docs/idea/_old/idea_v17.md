# idea_v17.md — v16 프루닝 미발동/더블쇼크 문제 해결 아이디어 평가

> 출처: /synod idea 세션 (Claude Judge + Gemini flash/high Architect + OpenAI gpt4o Explorer, Solver 라운드
> 실 병렬 교차검증, conf 95(can_exit=true) / 85(can_exit=false) — 5번 아이디어(전체 리셋)에 대해 두 모델이
> 독립적으로 동일한 결론(전체 리셋 기각, "State-Only Reset" 채택)에 도달해 Critic 라운드 생략)
> 기반: `docs/review/review_v10.md`, `uni-section/results/results_v16/uni_section_v16.md`(실측 로그)
> 목적: v16 실행 결과 확인된 두 가지 문제 — **(A) 프루닝 트리거 단 한 번도 미발동**(ewma_z가 임계값 0.08 근처도
> 못 감), **(B) epoch100 Stage2 진입 시 "더블 쇼크"**(MpErr 1.3%→16.9% 급등, area 급락 후 epoch219경 회복)
> — 에 대한 5개 대응 아이디어를 평가한다. 본 문서는 **아이디어 평가 문서**이며, 실제 코드 구현 지시서는
> 채택된 아이디어를 종합해 별도 `command_v17.md`로 작성한다.

## 1. 핵심 진단 (실측 로그 근거)

- `results_v16/uni_section_v16.md`: 최종 `ewma_z=[1.0, 1.0, 0.969, 0.954, 0.958]` — 프루닝 후보(Inner
  Hat/Patch1/Patch2) 전부 임계값(0.08)에 한참 못 미침. `l_sparse`는 0.47~1.0 사이 노이즈성 등락만 있을 뿐
  하강 추세가 없음.
- 같은 로그에서 epoch99→119 구간: `MpErr 1.30%→16.88%`, `area 895.4→652.5`, `loss 148→545` 급변 후
  epoch219경 재수렴(`MpErr 0.35%`). 원인은 두 가지가 겹침:
  1. **ALDA 승수 권선(windup)**: Stage1(두께 동결) 동안 `g_Mp` 위반이 계속 관측되는데도 actuator(두께)가
     얼어있어 고칠 수 없으니 `mu_Mp`만 계속 누적(epoch99 시점 이미 340).
  2. **더블 쇼크**: `gate_active`가 `STAGE2_EPOCH`에 직결되어, 두께 언락·옵티마이저 모멘텀 리셋·게이트
     활성화 3가지가 한 epoch에 동시 발동 — `command_v13.md`가 "두께 언락과 프루닝 시작을 다른 시점에"라고
     명시적으로 경고했던 패턴이 v16 코드 구조상 재발.

## 2. 아이디어별 평가

### 아이디어 1 — 후보군 축소 (`CANDIDATE_PARTS=[3,4]`, `S_PROTECT=[0,1,2]`)

**판정: 채택**

- Inner Hat(#06)은 하중경로상 구조재로, review_v10.md/command_v12.md가 이미 "1차 protect={0,1,2}, 후보는
  패치 {3,4}로 한정"을 권고한 바 있다. 후보를 2개로 좁히면 위상 탐색 공간이 2³=8에서 2²=4로 줄어 희소화
  압력이 분산되지 않고 Patch1/Patch2에 집중된다.
- 트레이드오프: 이론적 최대 경량화 폭은 줄지만, 구조적 타당성과 학습 안정성이 크게 개선된다.

### 아이디어 2 — w_sparse 상향 + Mp err 게이팅

**판정: 채택(파라미터 제약 조건부)**

```
w_sparse_effective = w_sparse × sigmoid(k × (tau_gate − mp_err))
```

- v16에서 `l_sparse`가 노이즈처럼 보인 이유는 `w_sparse=0.05`가 ALDA의 강한 Mp 제약 압력을 이길 만큼
  세지 않았기 때문이다. `w_sparse`를 0.15~0.2로 올리되, Mp err가 충분히 낮을 때만(`tau_gate≈0.05`, 5%)
  강해지도록 게이팅해야 조기 삭제로 인한 하중경로 붕괴(command_v13.md §3 경고)를 막을 수 있다.
- 권장 초기값: `tau_gate=0.05`, `k=50`(완만하되 뚜렷한 전환).

### 아이디어 3 — 엔트로피 정규화 추가 (review_v10.md A-7)

**판정: 조건부 채택 (게이트 활성 구간에서만)**

```
H(z) = -mean(z·log(z+ε) + (1-z)·log(1-z+ε))
```

- z가 0.95 같은 "회색지대"에 머무는 현상(v16 실측과 정확히 일치)을 완화하려면 이 항이 필요하지만,
  **학습 초반부터 걸면 z가 탐색도 하기 전에 1.0으로 조기 고착**될 위험이 있다(review_v10.md 원 경고와 동일).
- `gate_active`가 True인 구간에서만 활성화하고, `alpha_ent`를 Mp err와 결합(또는 아이디어2의 게이팅 신호를
  공유)해서 물리 제약이 안정된 뒤에만 세게 작동하도록 해야 한다.

### 아이디어 4 — 더블 쇼크 분리 (`GATE_ACTIVE_EPOCH` 분리)

**판정: 채택**

- v16 진단의 (B)를 직접 겨냥한 수정이다. `GATE_ACTIVE_EPOCH = STAGE2_EPOCH + 30`처럼 텀을 둬서, 두께가
  언락되고 어느 정도 안정된 뒤에만 게이트/프루닝 트리거가 개입하도록 한다.
- 두 모델 모두 이 아이디어가 4개 아이디어 중 "가장 직접적으로 관찰된 문제를 겨냥한 수정"이라는 점에 동의.

### 아이디어 5 — 부재 삭제 후 전체 리셋

**판정: "완전 리셋"은 기각, "State-Only Reset"(부분 리셋)으로 대체 채택**

두 모델이 독립적으로 동일한 결론에 도달했다(Gemini conf 95 can_exit=true / OpenAI conf 85, 세부 정밀도는
Gemini가 더 높으나 결론은 완전히 일치).

| 항목 | 완전 리셋(Hard Restart, 기각) | State-Only Reset(부분 리셋, 채택) |
|---|---|---|
| 모델 가중치 | 재초기화(파괴) | **보존** |
| 옵티마이저 state | 재생성 | **재생성**(모멘텀 완전 flush) |
| ALDA 승수(mu_Mp/mu_col) | 초기값으로 리셋 | **초기값으로 리셋**(권선 해소) |
| epoch/커리큘럼 | 0으로 리셋 | **리셋 안 함** — 대신 20epoch 쿨다운(프루닝 트리거 일시 정지) |
| 학습 비용 | 후보 2개 기준 최대 3×300=900epoch | 거의 추가 비용 없음(연속 학습) |

**기각 근거(완전 리셋)**:
1. v16은 A-5(그래프 수술)를 명시적으로 범위 밖에 뒀다 — 노드/엣지 수, 파라미터 shape는 삭제 전후로
   **전혀 바뀌지 않는다**. `command_v13.md §5`가 "옵티마이저 전체 재구성 필수"라고 한 근거(Adam step
   counter 불일치로 인한 순간 6배 과대 스텝)는 **파라미터 집합이 바뀌는 그래프 수술 상황**을 전제한
   것이다. v16의 soft-zero는 파라미터 집합이 그대로이므로 이 근거가 "가중치까지 통째로 버리라"는
   결론으로 확장되지 않는다 — 두 모델 모두 이 구분을 명시적으로 지적했다.
2. 이미 학습된 두께 분포(생존 파트들의 최적화된 두께)를 가중치 재초기화로 버리는 것은 수학적으로
   불필요한 손실이다. 좌표계·형상이 안 바뀌었는데 처음부터 다시 배울 이유가 없다.
3. 비용: 후보가 최대 3개(1번 아이디어 채택 시 2개)까지 있는 현재 설계에서, 삭제마다 300epoch를 처음부터
   돌리면 학습 시간이 실질적으로 감당하기 어려워진다.

**채택 근거(State-Only Reset)**:
1. v16의 진짜 문제는 "가중치가 낡았다"가 아니라 **"옵티마이저 모멘텀과 ALDA 승수가 삭제 이전 상태를
   그대로 들고 있다"**는 것이다. `log_alpha[pid]=-10.0` 대입은 순간적인 점프인데, AdamW의 1차/2차 모멘트
   버퍼는 "그 파트가 아직 존재하던 시절"의 그래디언트 통계를 담고 있어 삭제 직후 분포 밖(out-of-distribution)
   업데이트를 유발할 수 있다.
2. ALDA `mu_Mp`/`mu_col`도 삭제 이전 형상 기준으로 누적된 값이라, 삭제 후 새 형상에는 과도할 수 있다
   (아이디어4가 별도로 다루는 Stage2 진입 시 windup과 같은 종류의 문제가 삭제 이벤트에서도 재발할 수 있음).
3. 완화책: 삭제 확정 시 **(a)** AdamW를 현재 파라미터로 재인스턴스화(모멘텀 flush, 파라미터 값은 유지),
   **(b)** `mu_Mp`, `mu_col`을 초기값으로 리셋(`rho`는 유지해도 무방), **(c)** 이후 20epoch 동안 프루닝
   트리거 판정을 일시 정지(쿨다운 — command_v12.md의 avalanche 방지 쿨다운과 같은 취지, 연쇄 삭제 방지).

## 3. 아이디어 간 상호작용 (OpenAI Explorer가 제기한 쟁점)

- **1번(후보축소) ↔ 5번(리셋)**: 후보를 2개로 줄이면 삭제 이벤트 자체의 빈도가 줄어 5번의 필요성/비용
  부담이 자연히 낮아진다. 하지만 "빈도가 낮다"는 것이 "메커니즘이 불필요하다"는 뜻은 아니다 — 삭제가
  단 1회뿐이어도 그 순간의 모멘텀/승수 오염 문제는 동일하게 발생하므로 State-Only Reset은 유지한다.
- **4번(더블쇼크분리) ↔ 5번(리셋)**: 두 아이디어는 **서로 다른 이벤트**를 겨냥한다 — 4번은 "Stage2 진입"
  이라는 스케줄 이벤트, 5번(수정안)은 "부재 삭제 확정"이라는 프루닝 이벤트. 중복이 아니라 상호 보완이다.
  다만 두 이벤트가 우연히 겹치는 경우(쿨다운 직후에 Stage2 진입 등)를 피하도록 일정 조율이 필요하다.
- **2·3번(희소화 강화) ↔ 5번(리셋)**: 희소화가 강해질수록 삭제가 더 자주/빨리 발생할 수 있으므로, 5번의
  쿨다운 메커니즘이 "연쇄 삭제로 인한 반복 리셋 폭주"를 막는 안전장치 역할도 겸한다.

## 4. v17 종합 방향 (command_v17.md 작성 시 반영)

1. `CANDIDATE_PARTS=[3,4]`, `S_PROTECT=[0,1,2]` (아이디어1)
2. `w_sparse` 0.05→0.15, Mp err 게이팅(`tau_gate=0.05`, `k=50`) (아이디어2)
3. 엔트로피 정규화, `gate_active` 구간에서만 + Mp err 결합 (아이디어3)
4. `GATE_ACTIVE_EPOCH = STAGE2_EPOCH + 30`으로 게이트 활성화 시점 분리 (아이디어4)
5. 부재 DELETED 확정 시 **State-Only Reset**: 옵티마이저 재인스턴스화(가중치 유지) + ALDA mu 리셋 +
   20epoch 프루닝 트리거 쿨다운 (아이디어5, 수정 채택)

## 부록: 숙의 과정

- **Solver 라운드**: Gemini(flash — pro는 이번에도 rate-limit되어 폴백, thinking high, conf 95,
  can_exit=true) — 5개 아이디어 전체에 대해 표 기반 정량 비교, 특히 5번에서 "Complete Reset vs State-Only
  Reset" 대조표와 Adam 모멘텀 오염 메커니즘을 구체적으로 제시. OpenAI(gpt4o, conf 85, can_exit=false) —
  세부 정밀도는 낮지만 5번에 대해 "그래프 구조가 안 바뀌었으니 그래프수술 근거가 그대로 적용되지 않는다"는
  핵심 논지에 독립적으로 도달, 아이디어 간 상호작용(1↔5, 4↔5) 쟁점을 추가 제기.
- **합의**: 5개 아이디어 모두 두 모델 간 실질적 이견 없음(3번의 "조건부"라는 판정과 5번의 "완전 리셋
  기각/부분 리셋 채택"이라는 결론까지 일치) — Critic/Defense 라운드 없이 Judge 종합으로 진행.
