## 0. 목표 재정의 (확정)

**목표 = 위상 경량화(Topology Lightweighting).**
부재 두께를 하한선 이상으로 "지키는" 것이 아니라, **두께가 일정 수준 이하로 내려가는 부재는 아예 제거하여 질량을 줄이는 것**이 목적입니다. 즉 부재 소거는 회피 대상이 아니라 **원하는 결과**입니다.

- 유지할 것: 목표 소성 모멘트 $M_p$ (err < 2%), 충돌 비관통 제약, 메쉬 순서.
- 최소화할 것: 질량(= 살아있는 부재의 면적×두께 합).
- 판단할 것: **어떤 부재를 없앨지**를 사람이 지정하지 않고 **학습이 스스로 발견**.

### ⚠️ 핵심 기술 제약 (반드시 고려)
현행 충돌 회피는 **9개 부호 고정 앵커 쌍(sign-anchored pairs)**을 **고정 부재 수(5개)** 전제로 계산합니다.
부재를 **실제로 삭제**하면 인접행렬 차원이 바뀌고 앵커 쌍이 깨져 **그래디언트 단절·솔버 발산**이 발생합니다.
→ 그래서 "실제 삭제"가 아니라 **차원을 유지한 채 부재를 무력화**하는 방식이 필요합니다.

## 1. 권장 아키텍처 (숙의 최종안)

크리틱 라운드에서 초기 제안(L₁/₂ 희소화 + 3단계 커리큘럼 + 하드 프리징)이 여러 결함으로 기각되고, 다음 4가지 원칙으로 수렴했습니다.

### 원칙 A — 두께가 아니라 "존재 확률"을 학습 (핵심 전환)
연속 두께 $t$를 0으로 미는 대신, 부재마다 **미분 가능한 이진 존재 게이트** $z_i \in [0,1]$를 도입하고 두께를 분리합니다.

$$
t_i = z_i \cdot t^{\text{raw}}_i, \qquad z_i = \text{HardConcrete}(\phi_i)\ \ (\text{L0 완화})
$$

- $z_i$: 부재 $i$가 존재하는지(1) 사라지는지(0). $t^{\text{raw}}_i$: 존재할 때의 최적 두께.
- **존재 여부와 최적 두께를 독립적으로 학습** → 하이퍼파라미터 민감도가 급감.
- **왜 L₁/₂를 버리는가:** $L_{1/2}=\sum\sqrt{t_i}$는 $t\to0$에서 기울기가 발산(NaN 위험)하고 $\epsilon$-스무딩이 또 다른 튜닝을 낳음. **Hard-Concrete(L0 relaxation)** 가 NAS·구조 프루닝에서 수렴성이 검증됨.
- 경량화 압력은 게이트에 대한 **L0 패널티** $L_{0}= \lambda_0 \sum_i \Pr(z_i>0)$ 로 부여.

### 원칙 B — 커리큘럼이 아니라 "동시 최적화 + 어닐링" (닭-달걀 회피)
"Stage1에서 $M_p$ 확보 → Stage2에서 부재 제거 → Stage3에서 재보상"은 **$M_p$가 붕괴했다가 복구되는 비연속 경로**라 진동·국소최적에 갇힙니다.
대신 **처음부터 노드+두께+게이트를 동시 최적화**하고, $\lambda_0$를 **낮게 시작해 에폭에 따라 점진 증가(annealing)**시켜 불필요한 부재가 **자연스럽게 도태**되게 합니다.

$$
L = L_{M_p} + w_{area}\,\text{Mass}(z,t) + \lambda_0(\text{epoch})\,L_0 + w_{coll}L_{coll} + w_{order}L_{order}
$$

- $\lambda_0(\text{epoch})$: 0 → 목표값으로 코사인/선형 어닐링. 초기엔 성능 확보, 후기엔 희소화 우위.
- $M_p$는 게이트가 서서히 닫히는 동안 살아있는 부재가 **연속적으로 하중을 재분배**하며 유지.

### 원칙 C — 하드 프리징 금지, 학습 내내 소프트, 하드컷은 추론에서만
임계값에서 `requires_grad=False`로 동결하면 손실 지형에 **불연속 절벽**이 생겨 역전파가 끊깁니다.
→ 학습 중에는 $z_i$를 **연속 소프트 게이트로 끝까지 유지**하고, **최종 추론 시점에만** $z_i<\tau$ 부재를 하드 컷($z_i:=0$)으로 확정합니다.

### 원칙 D — 충돌은 "violation 항"에 게이트를 곱해 무력화 (⚠️ 코드 검증으로 수정됨)
사라지는 부재의 충돌 쌍을 통째로 꺼버리면, 살아있는 부재가 그 **유령 영역을 침범**하고, 나중에 되살릴 때 **자리가 없어 부활 불가(데드락)**가 될 수 있습니다.

> **초기안 폐기:** 애초 `clearance_k ← clearance_k·z_iz_j`(clearance 수축)를 제안했으나, **코드 검증 결과 이는 버그**입니다. `uni_section_v10.py`의 `build_collision_spec`에서 `clearance = min(0.5, slack − 0.05)`로 **음수가 될 수 있어**, 음수 clearance에 $z→0$을 곱하면 값이 0으로 **증가**해 오히려 없어지는 부재에 충돌 패널티가 새로 생깁니다(부호 반전 역설).

→ 올바른 방법: clearance·sigma·proj 계산은 그대로 두고, **최종 violation 항 전체에 존재 게이트를 곱합니다.**

$$
\text{gap}_{ij}=\sigma\cdot\text{proj}-\tfrac{t_i+t_j}{2}-\text{clearance},\qquad
\text{violation}'_{ij}= z_i\,z_j\cdot\big(\text{relu}(-\text{gap}_{ij})\big)^2
$$

- 두께 항 $-(t_i+t_j)/2$는 이미 $t_i=z_i t^{\text{raw}}_i$로 게이트되므로, 사라지는 부재는 접촉 압력을 **자동으로 놓습니다**. 다만 기하 항 $\sigma\cdot\text{proj}$(중심선 겹침)는 $t=0$에서도 남으므로 violation에 $z_iz_j$를 곱해 완전 무력화가 필요합니다.
- 앵커 쌍의 개수·차원(9-앵커)은 그대로 유지되어 스킴이 깨지지 않습니다.

## 2. 필수 부재 자동 보호 (사람이 라벨링하지 않음)

"제거할 부재를 발견"하는 것이 목적인데 외곽 부재를 손으로 지정하면 모순입니다.
→ **경계조건 기반 그래프 연결성 분석으로 자동 보호**: 지지점(support)·하중 재하점(loading point)에 직접 연결된 노드를 포함하는 부재는 그래프 연결성 검사로 **자동으로 보호 마스크**($L_0$ 패널티 면제, $z=1$ 고정) 부여. 단면의 **폐합(closed-loop) 붕괴**를 막는 최소 연결도 연결성 검사로 강제합니다.

## 3. 권장 실행 스펙 (요약)

| 항목 | 권장 |
|------|------|
| 설계 변수 | 노드 위치 + $t^{\text{raw}}_i$ + 존재 게이트 $z_i$ |
| 게이트 | Hard-Concrete (L0 relaxation), $t_i=z_i t^{\text{raw}}_i$ |
| 경량화 손실 | $\lambda_0(\text{epoch})\sum \Pr(z_i>0)$, $\lambda_0$ 어닐링 (0→목표) |
| 최적화 방식 | **처음부터 동시(joint)**, 단계 분리 없음 |
| 충돌 처리 | **violation 항에 $z_iz_j$ 곱** (clearance 수축 아님 — §5 버그 참조) |
| 프리징 | 학습 중 없음(소프트 유지), **추론 시** $z<\tau$만 하드컷 |
| 필수 부재 | 경계노드 그래프 연결성으로 **자동 보호** |
| $M_p$ 회복 | 게이트가 닫히는 동안 노드 재배치+생존부재 두께로 연속 보상 |

권장 임계 $\tau$는 학습 후 $z_i$ 분포가 0/1로 양극화된 것을 확인한 뒤 골(valley)에서 결정 (예: 0.5). 양극화가 안 되면 $\lambda_0$ 어닐링 상한을 높입니다.

## 5. 코드 검증 (`uni_section_v10.py` 대조) — ⚠️ 필수 수정 사항

실제 코드를 대조한 결과, 위 아이디어가 **현행 코드에서 그대로는 동작하지 않는** 지점이 여러 개 확인되었습니다. Gemini·OpenAI(o3) 두 리뷰어가 독립적으로 동일 결론에 도달했습니다.

### 🔴 [BLOCKER] mass loss가 경량화를 정면으로 방해
`compute_mass_loss`: `l_mass = ((area − target_area)/target_area)²`, 여기서 `target_area = 초기 단면적 스냅샷`.
→ 면적이 **줄어들면 손실이 증가**(양방향 제곱 패널티). 즉 **부재를 제거하면 오히려 벌점**을 받습니다. 경량화를 보상하는 항이 코드에 **전혀 없습니다.** 이 항을 고치지 않으면 프루닝은 원리적으로 불가능합니다.
**수정:** 초기면적 보존형을 **단방향 상한 패널티 + 게이트 희소화 보상**으로 교체.
```python
# area 상한만 처벌(초과분), 감소는 처벌하지 않음
over = torch.relu(area - target_area) / target_area
l_mass = over**2 + lambda0(epoch) * torch.mean(z)   # mean(z) = L0 완화 희소화 동력
```
그리고 `mass_gate = gate * sigmoid(10*(0.05 - mp_rel_err))`도 재검토(희소화와 충돌 가능).

### 🔴 [BLOCKER] T_MIN=0.1mm 하한이 "완전 제거"를 막음
`t_final = T_MIN + (T_MAX−T_MIN)·sigmoid(logit + delta_t)` → **두께가 0.1mm 밑으로 못 내려감.** $z$를 곱해도 `t=z·(0.1+…)`인데 T_MIN이 게이트 안쪽에 있으면 0이 안 됩니다.
**수정:** 게이트를 **T_MIN 바깥**에 적용. 즉 `t_raw = T_MIN + (T_MAX−T_MIN)·sigmoid(...)` 계산 후 `t_final = z_i · t_raw` (게이트 경로에서 T_MIN=0 효과). $z_i→0$일 때 물리 두께가 진짜 0이 되도록 보장.

### 🔴 [BUG] 충돌 clearance 수축안은 폐기 (§ 원칙 D 참조)
`clearance`가 음수 가능 → `clearance·z`는 부호 반전 역설. **violation 항에 $z_iz_j$를 곱하는 방식으로 확정.**

### 🟡 $z$ 게이트를 곱해야 하는 정확한 위치 (4곳)
부재가 "존재하지 않으면" 질량·강성·충돌 기여가 모두 0이어야 합니다. 두께 축소만으로는 불충분(Mp/면적 합산이 t를 직접 사용).
1. **두께/면적:** `t_final_i = z_i · t_raw_i`, `edge_area = length · t_final`.
2. **Mp (`compute_edge_mp_pna`):** 게이트된 `t_final` 사용 (Mp는 t 비례이므로 $z_i$ 자동 반영).
3. **mass:** 위 area가 이미 게이트됨.
4. **충돌 (`compute_collision_loss_v5`):** `violation *= z_i·z_j`.

### 🟡 `verify_thickness_gradient` 사전검증 충돌
이 함수는 학습 전 `dMp/dt > 0`을 **강제(assert)**합니다. $z_i=0$이면 $dMp/dt=0$이 되어 검증 실패.
**수정:** ① 초기 게이트를 $z_i≈1$(sigmoid 프리액티베이션 ≥ 5)로 시작해 초기 검증 통과 보장, ② 또는 assert를 `z_i>ε`인 부재로 한정.

### 🟡 기존 2단계 `thickness_gate` 스케줄 ↔ λ₀ 어닐링 중복
현행 `thickness_gate = sigmoid(0.6·(epoch−128))`(2단계 두께 학습)와 새 λ₀ 어닐링이 **이중 스케줄**로 충돌 소지.
- **선택지 A (Gemini):** 기존 Stage 2 게이트에 λ₀ 어닐링을 **동기화**(Stage 2 진입 후 희소화 시작) — 코드 변경 최소.
- **선택지 B (o3):** 기존 `thickness_gate`/`mass_gate` 스케줄을 **제거**하고 λ₀ 단일 스케줄로 통합 — 더 깔끔하나 재보정 필요.
- **판정:** 우선 **선택지 A**로 안정적으로 프루닝을 확인한 뒤, 필요 시 B로 단순화 권장.

### 🟡 경계 자동 보호는 구현 부담 존재
현재 코드엔 연결성 기반 보호 로직이 없음(collision_spec·part indexing 의존도 높음). **1차 구현에선 보호 파트 인덱스를 상수(예: `S_protect={0,1}` = Outer Hat, Inner Plate)로 지정**하고, 자동화(경계노드 그래프 분석)는 후속 과제로 분리 권장.

<summary>숙의 과정 (Synod)</summary>

**모델 기여**
- **Gemini (Architect):** 가상 프루닝 개념, L0 게이트($t=z\cdot t_{raw}$), 동시 최적화+어닐링, clearance 박스 수축, 경계조건 자동 보호 제시.
- **OpenAI (Explorer):** 3단계 커리큘럼의 진동/수렴실패 위험, 하드 프리징 불연속, 유령영역 충돌 루프홀, 임계값 자동화 필요성 지적.
- **Claude (Validator):** 9-앵커 고정 부재수 제약이 하드 삭제와 충돌함을 프레이밍, 각 대안이 이 제약을 위반하지 않는지 검증.

**해결된 주요 쟁점**
1. 희소화 수단: L₁/₂ (발산 위험) → **Hard-Concrete L0 게이트**.
2. 학습 구조: 3단계 커리큘럼 (Mp 붕괴·진동) → **동시 최적화 + λ₀ 어닐링**.
3. 부재 무력화: 하드 프리징·충돌 마스킹 (불연속·유령영역) → **소프트 게이트 + violation에 $z_iz_j$ 곱**, 하드컷은 추론 시만.
4. 필수 부재: 수동 라벨링 → 1차 상수 보호셋, 후속 자동화.
