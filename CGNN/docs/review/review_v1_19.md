## §2 수정 내역

### §2.1 강체 이동을 "학습이 모두 끝난 뒤"로 분리 (v1.19 §2)

v1.18까지 강체 이동은 Stage4 **진입 직전**에 1회만 실행됐고, 그 뒤 Stage4의 200 epoch 동안
두께가 계속 학습되면서 이동량이 낡은 값이 됐다. 학습 종료 후 **항상 1회** 실행되는 최종 정렬
단계(`apply_final_flange_alignment`)를 추가하고, 버퍼는 덮어쓰지 않고 **누적(`+=`)** 하도록 했다
— Stage4가 이미 적용한 이동(d1)을 보존하고 잔차(d2)만 더하는 2단 구조다.

부수적으로, Stage4 진입 조건(`enter_stage4 = ambiguous > 0`)이 플랜지 간극 상태와 무관하다는
**잠재 결함**도 이 구조가 함께 방어한다(게이트가 처음부터 깨끗하게 수렴하면 Stage4를 건너뛰어
보정 기회가 사라진다). 다만 이번 실행들에서 실제로 발생한 일은 아니었다 — review_v1_18.md
상단 정정 고지 참고.

### §2.2 이동량 계산 입력을 export와 동일한 스냅샷으로 통일 (v1.19 §3/§6)

1차 실행에서 잔차 −0.0133~−0.0135mm가 남았다. 원인은 `train_step_multi()`가
`forward → backward → optimizer.step()` 순서라 반환하는 `t_final`이 **그 epoch의 마지막
업데이트 직전** 값인 반면, export는 업데이트 후 eval forward를 새로 돌려 쓰기 때문이었다.
`_eval_snapshot()` 헬퍼로 **export가 실제로 쓸 좌표·두께**를 떠서 이동량을 계산하도록 통일했다.

- 검증(저장 가중치 재계산): 잔차 **0.0135mm → 0.000001mm**, 추가 보정량 0.0133mm가 진단과 일치.

### §2.3 Patch2의 부모를 Inner → Plate로 변경, Inner–Patch2를 종속 쌍으로 분리 (v1.19 §10)

2차 실행에서 Plate–Patch2가 −0.7001mm 파고들었다. 확인 결과 **적층 순서가 뒤집혀** 있었다:

```
초기 형상:  Patch2(11.23) < Plate(12.83) < Inner(14.43)   ← 올바름
2차 실행:   Plate(12.90) < Patch2(13.18) < Inner(14.78)   ← Patch2가 Plate를 관통
```

원인은 두 가지가 겹친 것이다:
1. `compute_rigid_shift()`가 Patch2를 **Inner 기준**(`mean_shift(2,4)`)으로 배치했다 — 물리적
   이웃은 Plate인데 한 겹 건너뛴 Inner에 맞춰 붙이면 Plate를 뚫는다.
2. Inner–Patch2 3쌍이 `FLANGE_PAIR_SPEC`에 **접촉 쌍으로 등록**돼 있었다. 실제로는 사이에
   Plate가 끼어 닿을 수 없는 쌍이고 정상 간극이 곧 Plate 두께인데(초기 실측 +1.6000mm =
   당시 Plate 두께), 강체 이동이 이 정상값을 오차로 보고 닫으려 했다.

수정: (a) `mean_shift(1,4)`로 변경, (b) Inner–Patch2를 `FLANGE_SANDWICH_DERIVED_SPEC`으로 분리해
강체 이동·공차 판정에서 제외하되 **적층 순서 검증용 참고 지표**로 리포트에 남김.

이 쌍은 수학적으로 종속량이다 — Patch2–Plate와 Plate–Inner가 모두 접촉하면
`d(Inner,Patch2) = (t_P+t_2)/2 + (t_P+t_I)/2`이므로 간극 = `t_Plate`가 자동 성립한다. 독립적으로
제어할 수 있는 양이 아니므로 제약으로 두는 것 자체가 과잉 구속이었다.

- 검증: 수정 후 Plate–Patch2 = −0.0000mm, Plate–Inner = −0.0000mm, Inner–Patch2 = **+1.2628mm
  (= 그 시점 Plate 두께와 정확히 일치)**, 적층 순서 Patch2 < Plate < Inner 보존.

### §2.4 CSV·리포트 두께를 생존 floor 기준으로 수정 (v1.19 §11)

3차 실행에서 Plate–Patch1 10건이 위반(+0.6343mm)으로 찍혔으나, **형상이 아니라 두께 표기가
틀린 오탐**이었다. `export_final_section_csv()`가 파트 두께를 17 floor **전체** 노드로 평균했는데,
candidate 파트는 삭제 floor가 별도 두께 그룹으로 pooling되므로 생존/삭제 구간이 섞인다:

| Patch1 | t_raw |
|---|---:|
| floor 0~4 (생존) | **2.4977** |
| floor 5~16 (삭제) | 0.7007 |
| 17 floor 평균 (CSV·리포트 기록값) | **1.2292** ← 실제의 절반 이하 |

강체 이동은 노드별 `t_final`을 쓰므로 형상은 처음부터 정확했다(실제 간극 +0.0001mm).
문제는 **기록된 숫자를 사후 검증 코드가 그대로 읽어 합부를 판정**하고, 제조 쪽도 이 값을
쓴다는 점이었다. 생존 floor 노드만 평균하도록 수정하고(리포트 §4 표의 단일 run 경로도 동일),
run별 두께가 갈려 CSV로 표현 불가능한 경우 경고를 출력하도록 했다.

- 검증(같은 가중치로 재export): Patch1 두께 1.2292 → **2.4977**, 간극 위반 **10건 → 0건**.

### §2.5 검증 인프라 보강 (v1.19 §1/§7/§8/§9)

| 항목 | 내용 |
|---|---|
| §1 `compute_flange_gap_stats()` | 기존 진단은 `margin < 0`(겹침)만 셌다 — v1.18의 실패 모드인 **간극 벌어짐은 위반으로 치지 않아** 학습 내내 "위반 0개"라는 거짓 안전 신호를 출력했다. 양방향으로 교체. 판정 기준도 절대 간극이 아니라 **캘리브레이션 대비 편차**로 잡아, gap0가 0이 아닌 것이 정상인 쌍의 오탐을 없앴다 |
| §7 fail-fast 판정 범위 | 중단 판정이 `dy_part` **전체** 최댓값이라, 최종 설계에 존재하지도 않는 삭제 파트가 임계를 지배했다(실측 v1.17/18/19에서 매번 Patch2가 임계 3.0mm의 76~80%를 차지). 실존 파트로 한정 — 소진율 77% → 13% |
| §8 `check_flange_gap_from_csv()` | 리포트에 겹침 검사만 실리고 간극은 콘솔에만 나와, v1.18의 25배 초과 간극이 은폐됐다. **export된 CSV를 다시 읽어** 검사하는 짝 함수를 추가해 리포트 §6으로 기록 |
| §9 per-epoch 로그 | 학습 로그에 양방향 편차 `fdev=±X(N)` 추가 |

§8이 신뢰할 만한지는 과거 산출물 3종으로 교차 확인했다 — v1.18(+0.2520mm, 214건),
v1.19 1차(−0.0135mm, 204건), v1.17(**위반 0건**)이 모두 수작업 계산값과 일치했다. 정상인
v1.17을 통과시킨다는 점에서 오탐이 없음도 확인된다.

## §3 이번 작업에서 드러난 공통 패턴

네 결함은 표면적으로 달라 보이지만 **모두 "종속량을 독립적으로 다룬" 오류**라는 공통점이 있다.

| 결함 | 종속 관계 | 잘못 다룬 방식 |
|---|---|---|
| §2.1 | 이동량은 **그 시점 두께에 종속** | 두께가 더 변할 것을 모르고 한 번만 계산 |
| §2.2 | 이동량은 **export가 쓸 두께에 종속** | 한 스텝 이전 값으로 계산 |
| §2.3 | Inner–Patch2 간극은 **다른 두 접촉에 종속** | 독립 접촉 쌍으로 등록해 과잉 구속 |
| §2.4 | CSV 두께는 **생존 구간에 종속** | 삭제 구간까지 섞어 평균 |

또 하나의 패턴은 **진단이 실패를 은폐한 구조**다. 겹침 검사는 간극 방향을 구조적으로
통과시키고(밴드가 안 겹치면 "이상 없음"), 간극 진단은 겹침 방향만 셌다. 두 검사가 서로의
사각지대를 덮지 못해, v1.18의 전면적 실패가 "겹침 0건"이라는 리포트로 남았다.

## §4 검증 방법 (재현용)

모든 수치는 학습을 다시 돌리지 않고 **저장된 산출물만으로** 재현 가능하다.

```python
import AI_design_v1_19 as m
CSV = r'reports/v1_19/final_section_v1_19.csv'
m.check_part_overlap(CSV, tol_mm=m.FLANGE_ASSERT_TOL_MM)        # 겹침
m.check_flange_gap_from_csv(CSV, tol_mm=m.FLANGE_ASSERT_TOL_MM) # 간극 + 적층 순서
```

저장 가중치(`weights/v1_19/*.pt`)로 eval 스냅샷을 떠서 export CSV와 대조하면 좌표가
0.0001mm 이내로 재현된다 — 형상 관련 주장을 사후 검증할 때 이 경로를 쓰면 된다.
단, `_stage4_rigid_active`는 버퍼가 아닌 일반 속성이라 `load_state_dict()`로 복원되지 않으므로
수동으로 `True`를 설정해야 export 당시 형상이 재현된다(`stage4_rigid_dy` 자체는 persistent=True).

## §5 남은 사항

### 5.1 미해결

- **`compute_flange_gap_margin_diag()`는 여전히 단방향**이다(겹침만 카운트). v1.19는 판정용
  신규 함수(§1)를 추가했을 뿐 이 함수는 로그 포맷 호환을 위해 그대로 뒀다. 학습 로그의
  `gap_margin=...(N)` 표기를 해석할 때 주의할 것 — 같은 줄의 `fdev=...(N)`이 양방향 값이다.
- **CSV 형식은 파트당 두께를 하나만 담는다.** 한 파트가 서로 다른 두께의 run 여러 개로
  갈리면 표현이 불가능하다. 현재는 평균 + 경고로 처리하지만, 실제로 그런 결과가 나오면
  CSV 규격 자체를 손봐야 한다.

### 5.2 v1.19 범위 밖 — 별도 판단 필요

- **두께 분기 경향**: Outer/Inner가 상한(2.5mm)에, Plate가 하한 쪽(0.70mm)에 몰린다. y좌표
  상한으로 깊이 성장이 막힌 결과로 보이며, 구조적으로 타당한 재료 배분인지는 설계 검토가
  필요하다. 참고로 v1.17(상한 2.3, y 제한 없음)에서는 세 파트가 모두 2.29~2.30으로 함께
  수렴했다.
- **Patch1/Patch2의 생존 패턴이 실행마다 크게 달라진다**(같은 코드에서 Patch2가 0/17, 1/17,
  17/17로 갈렸다). 경계값 근처의 불안정성으로 보이며, 어느 구성을 채택할지는 구조 검토
  대상이다.
- **Mp 달성률 97.3%**로 목표에 약 2.7% 미달이다(#08, #09만 초과 달성). 면적 감량 목표도
  100.6%로 근소하게 미달이다.

### 5.3 review_v1_18.md 정정 이력

v1.19 작업 도중, `review_v1_18.md`의 최초 근본 원인 진단("Stage4가 스킵되어 강체 이동이
한 번도 실행되지 않았다")이 **오진**임을 저장된 가중치·좌표 실측으로 확인해 정정했다
(log_alpha가 정확히 ±5.0 = Stage4 강제 이진화의 산물, `stage4_rigid_dy` 버퍼가 0이 아님,
