## 요약

command_v1_3.md의 §2(질량 역설 제거)·§5(Stage 4)는 **의도한 대로 동작했다** — 게이트는 완전히
포화(`log_alpha_sat` 무관, Stage4에서 `±5.0`으로 확정)했고, Mp는 목표 대비 101.0%로 물리적으로
만족되었으며, 감량 목표(95%, 22,854.1mm²)도 달성했다(19,905.0mm², 82.7%). 그러나 **목표를 과도하게
초과 달성**(−17.3%, 목표는 −5%)하는 과정에서 연속 부재 Plate(#03)가 하한 `T_MIN=0.7mm`에 완전히
포화했고, 이것이 **Inner(#06)가 Plate를 기하학적으로 뚫고 나오는 실제 충돌**로 이어졌다.
이는 v1.3 신규 코드(`contrib_mass`)만의 문제가 아니라, **v1.2부터 존재했던 `uni_section_v18.py`의
정적 충돌 스펙(clearance/σ가 초기 형상에서 1회만 계산)이 v1.3의 새로운 감량 압력 앞에서 노출된
구조적 약점**이다.

## 발견된 문제

### [ERROR] 1. Stage 4에서 면적이 목표 미달 후에도 계속 축소됨 — `l_mass` 예산 항이 아니라 `f` 항이 원인

- **근거**: epoch 499 시점 area=21,912.1mm², 이미 목표(22,854.1) 아래. `l_mass = relu(area/target-1)²`는
  이 시점부터 그래디언트가 정확히 0이어야 한다. 그런데 Stage 4(epoch 500→699) 동안 area가
  21,912.1 → 20,056.2로 **추가로 8.5% 더 줄었다.**
- **원인**: `usv18.compute_alda_loss()`의 `f = area / target_area`는 **relu 게이트가 없는 상시 선형
  항**이다(command_v1_3.md §2.1이 이미 문서화한 사실 — "제안 A의 핵심 메커니즘"). `l_mass`(예산 제약,
  목표 초과분만 벌점)가 0이 되어도 `f`는 계속 area를 아래로 민다. 이것이 §2의 의도된 동작(A안)이지만,
  **하한을 두지 않아 목표 초과 달성을 막을 방법이 없다.**
- **결과**: Plate(#03) 두께가 `T_MIN_V13=0.7`에 정확히 포화(`final t = 0.700`) — 옵티마이저가 그보다
  더 얇게 만들고 싶어 하지만 하드 클램프에 막힌 상태. 이는 command_v1_3.md §3.5-4가 candidate 패치에
  대해 경고했던 "T_MIN 진입 장벽"과 동일한 패턴이 **연속 부재(Plate)에서도 발생**한 것이며, §5.4는
  이를 "부재당 스칼라 1개 → 제조성 위험 없음"으로 낙관했으나 **이 낙관이 실측으로 반증되었다.**

### [ERROR] 2. 충돌 손실(`compute_collision_loss_v5`)이 얇아진 형상에서 과소 작동 — 정적 스펙의 구조적 한계

- **근거 (`uni_section_v18.py`, 불변 대상, v1.2부터 동일)**:
  ```python
  def build_collision_spec(coords, t, part_ids, section_ids, ...):
      # 학습 시작 전 "초기" coords·thickness로 단 1회만 호출됨
      slack = (sigma * vals).min().item() - (t_a0 + t_b0) / 2.0
      clearance = min(clearance_default, slack - init_buffer)   # ← 이 값이 학습 내내 고정
  ```
  `compute_collision_loss_v5()`는 매 스텝 `t_final`(현재 두께)로 `t_sum_half`를 다시 계산하지만,
  `clearance`와 부호 `sigma`는 **초기 형상 기준으로 박제된 값**을 그대로 쓴다. Plate가 1.6mm→0.7mm로
  얇아지면 `t_sum_half`가 줄어 `gap` 계산상 "여유"가 자동으로 생기는 것처럼 보이지만, 이 여유가
  실제 물리적 clearance를 반영하는지는 검증되지 않는다.
- **추가 근거 (Gemini 단독 지적, 코드로 확인됨)**: 위반량 계산이
  `violation = torch.relu(-gap).clamp(max=1.0)`로 **1.0mm에서 클램프**된다. 관통이 1.0mm를 넘어가는
  순간 이 항의 그래디언트가 정확히 0이 되어, 옵티마이저가 "이미 뚫은" 상태에서는 되돌아올 유인이
  완전히 사라진다.
- **추가 근거 (양 모델 공통)**: `compute_alda_loss()`의 `term_col`은 `rho_col`/`mu_col`이 고정
  상수다(이전 세션에서 이미 확인된 사실 — dual-ascent 갱신 코드가 호출되지 않음). 즉 충돌 페널티의
  "세기"는 **초기 스케일에 맞춰 튜닝된 채 학습 내내 재조정되지 않는다.**
- **결론**: 문제 1(면적 축소 지속)이 만든 압력이, 문제 2(고정·클램프된 충돌 손실)가 막지 못하면서
  Inner가 Plate를 기하학적으로 통과했다. 두 문제가 결합해야 실제 관통이 일어난다 — 어느 한쪽만으로는
  발생하지 않았을 가능성이 높다(Stage 1-3에서는 area가 21,000~22,000 부근에서 진동했을 뿐 계속
  붕괴하지 않았고, 관통도 보고되지 않았다).

### [WARNING] 3. `contrib_mass`(v1.3 신규)가 하한을 두지 않은 것은 command_v1_3.md 자체의 설계 공백

- command_v1_3.md §2.6은 "목표 초과분만 벌점"이라고 명시했고 §7.1도 "감량 목표는 확정"이라고만 했지,
  **"목표를 과도하게 초과 달성하는 것"을 막는 요구사항은 어디에도 없다.** 이번 관통은 신규 코드의
  버그라기보다, 스펙 자체가 상한(초과 달성 방지)을 고려하지 않은 데서 비롯된 **요구사항 공백**이다.
  §2.6.6의 완화 사다리(W_MASS 하향 등)는 전부 "감량이 안 될 때"의 방향만 다루고, "감량이 과할 때"는
  다루지 않는다.

### [INFO] 4. 정적 `sigma`(방향 부호) 자체는 근본 원인이 아님

- OpenAI가 정확히 지적: `sigma`가 고정된 것 자체는 위험하지 않다 — 실제로 반대편으로 넘어가면
  `sigma * proj`가 크게 음수가 되어 페널티가 오히려 **커진다.** 문제 2의 핵심은 `sigma`가 아니라
  `clearance`의 정적 절대값과 `.clamp(max=1.0)`의 그래디언트 소실, `rho_col`의 고정 세기다.

### [ERROR] 5. 34개 게이트 중 단 하나도 삭제되지 않음 — 엔트로피 항이 "삭제 유도"가 아니라 "현재 위치 강화" 항이기 때문

- **근거 (리포트)**: Patch1(#07)·Patch2(#08) 모두 17/17 섹션에서 `alive`로 종료(`존재` 열이
  `OOOOOOOOOOOOOOOOO`). `dead0=0/34`, `suspect=0`가 700 epoch 내내 유지. 게이트 평균값(`g3`/`g4`)은
  초기 ~1.000에서 시작해 epoch 499 시점 `g3=0.887`, `g4=0.937`까지만 하강 — 프루닝 임계 `0.08`은
  물론 이진화 임계 `0.3`, 중간값 `0.5` 근처에도 가지 못했다. Stage 4에서 최종적으로 `±5.0`으로
  확정된 것은 "삭제된 게이트가 살아남아서"가 아니라, **애초에 모든 게이트가 `BINARIZE_THRESHOLD(0.3)`
  이상이라 전부 존재(+5.0) 쪽으로 확정됐을 뿐**이다(§5.2 로직상 당연한 결과).
- **원인 (Gemini conf 98·OpenAI conf 92, 수학적으로 완전히 수렴)**: 엔트로피 손실
  `entropy(z) = -[z·log(z) + (1-z)·log(1-z)]`는 **대칭 함수**이며, 그 그래디언트는
  `∂L_ent/∂z ∝ -log((1-z)/z) = logit(z)`다. 즉 **z가 이미 0.5보다 크면 엔트로피는 z를 1 쪽으로
  더 밀고, 0.5보다 작으면 0 쪽으로 더 민다 — "삭제 방향"이 아니라 "현재 위치 강화 방향"으로 작동하는
  항이다.** `init_log_alpha=2.0`은 `z_init ≈ 0.986`(1에 매우 가까움)에서 시작하므로, 엔트로피는
  학습 시작부터 강하게 "존재" 쪽을 밀어붙인다.
  v1.2까지는 `w_sparse`(상수 페널티, 위치 무관하게 항상 0 쪽으로 미는 유일한 힘)가 이 강화 효과를
  상쇄했지만, v1.3 §2.1은 **질량 역설을 없애기 위해 `w_sparse`를 정확히 0.0으로 만들었다** — 그
  결과 "0 쪽으로 미는 유일한 방향성 힘"이 시스템에서 완전히 사라졌다. 남은 것은 면적 항(`f`)이 주는
  약한 물리적 유인뿐인데, 이는 엔트로피(계수 0.05)가 `z≈0.99` 부근에서 만드는 강한 복원력을 이길
  만큼 강하지 않았다(OpenAI: "order-of-magnitude smaller than 0.05·Entropy").
- **§2.6의 완화 사다리(§7 R1~R3)가 이 문제를 감지하지 못한 이유**: 세 롤백 규칙 모두 "사망(죽음)"
  이벤트를 트리거로 삼는다(`SUSPECT`/연쇄 붕괴/질량 역설 재발). **애초에 사망이 한 건도 발생하지
  않는 이번 케이스는 세 규칙 중 어느 것도 발동 조건을 충족하지 못한다.** 즉 "삭제가 전혀 안 되는"
  실패 모드는 command_v1_3.md §7의 감시망 밖에 있다.
- **이것이 실패인가**: 두 모델 모두 "물리적 실패는 아니지만 설계 목적상 회귀(regression)"로
  판정했다. Mp(101.0%)·감량 목표(82.7% 달성) 자체는 만족했으므로 **물리·질량 관점에서는 유효한
  결과**다. 그러나 게이팅 메커니즘 자체가 "선택(topology) 최적화"에서 사실상 "형상/두께만의 연속
  최적화"로 퇴화했고, 이는 command_v1_3.md가 유지하려 했던 존재-게이트의 존재 의의(불필요한 부재
  제거를 통한 부품 수 절감)를 무력화한다.

**권장 조치**:
1. **(OpenAI 1순위 제안, 최소 변경)** `init_log_alpha`를 `2.0 → 0.0`으로 낮춰 `z_init ≈ 0.5`(중립)에서
   시작하게 한다 — 엔트로피가 순수하게 물리적 유인이 이끄는 방향을 강화하는 역할만 하도록 만든다.
   한 줄 변경, "임의 페널티 없음"이라는 v1.3의 철학을 유지한다.
2. **(대안, Gemini 제안)** `W_SPARSE_V13`을 0이 아니라 아주 작은 값(0.02~0.05, §2.2 B안의 면적
   가중 버전 권장)으로 재도입해 위치 무관의 약한 삭제 방향성을 되살린다. 다만 이는 §1의 B안 가드
   조건(`USE_AREA_WEIGHTED_SPARSE=True`일 때만 유효)과 결합해야 하며, 단순 상수 재도입은 §2.1이
   고친 질량 역설을 재현할 위험이 있으므로 **1번 조치를 먼저 시도할 것**.
3. §7 롤백 규칙에 **R4(신규 후보)**: "`ASWC_STAGE2_END` 이후 N epoch 동안 어떤 게이트도 0.5 미만으로
   내려가지 않으면 경고"를 추가해, 이번처럼 삭제가 원천적으로 발생하지 않는 상황을 조기에 감지한다
   (SUSPECT death 트리거가 아닌 "삭제 기회 자체의 부재"를 감지하는 별도 지표).

## 권장 조치 (최소 개입, `uni_section_v18.py` 무수정 원칙 준수)

우선순위 순:

1. **Stage 4 진입 시점에 `collision_spec`을 현재 형상·두께로 재계산** — `uni_section_v18.build_collision_spec()`을
   `AI_design_v1_3.py`에서 한 번 더 호출(3단계 종료 시점 `new_coords`/`t_final` 사용)하면
   `clearance`/`sigma`가 "얇아진 이후" 기준으로 갱신되어 문제 2의 스케일 불일치를 크게 완화한다.
   기존 함수 재사용이므로 최소 침습.
2. **면적 하한 안전장치 추가** (`AI_design_v1_3.py` 신규, `uni_section_v18.py` 무관) —
   `l_mass`를 양방향 밴드로 확장: `torch.relu(1.0 - area/(SAFETY_RATIO*target_area))**2` 형태로
   목표의 90~92% 밑으로는 못 내려가게 하는 항을 Stage 4(또는 전체)에 추가. `SAFETY_RATIO`는
   신규 상수로 노출.
3. **Stage 4 전용 보조 충돌 페널티** — `.clamp(max=1.0)` 때문에 죽는 그래디언트를 보완하기 위해,
   기존 `collision_spec`을 재사용해 클램프 없는 이차 페널티를 `AI_design_v1_3.py` 안에서 추가
   계산하고 Stage 4 loss에만 더한다(원본 `compute_collision_loss_v5` 호출은 그대로 유지해 이중
   집계가 아니라 "보강"으로 취급).
4. (선택) 리포트에 파트쌍 최소 간극(`min gap`) 진단 표를 추가해, 다음 실행에서 관통이 재발하면
   학습 중간에 조기 발견할 수 있게 한다 — §7 롤백 규칙(R1~R3)과 같은 성격의 R4 후보.

**적용 순서**: 1번(무료에 가까운 재계산)을 먼저 적용해 재학습해보고, 그래도 관통이 남으면 2·3번을
추가한다. 4번은 회귀 방지용이므로 언제 넣어도 무방하다.

**모델 기여**
- **Gemini (flash, conf 98)**: `violation.clamp(max=1.0)`이 관통 1mm 이상에서 그래디언트를 완전히

  Stage4의 지속적 면적 축소의 진짜 동력임을 정확히 지목. `sigma` 고정은 원인이 아니라는 반론도
  정확함(방향이 바뀌면 페널티가 오히려 커지므로).
- **Claude (오케스트레이터)**: 두 모델의 진단을 실행 로그 수치(epoch 499 이후 area가 이미 목표 밑인데

  분리해 명시.
