# idea_v1_16.md — Y축 전용 파트 강체 이동으로 테이퍼 중첩 근본 해결

> **참고**: 이 문서는 이전에 같은 경로에 있던 "v1.16 하이브리드(강체 정렬+Plate 노드 해제)" 아이디어를 **대체**한다. 그 아이디어를 구현한 실제 코드(`AI_design_v1_16.py`)는 실행 결과 겹침이 v1.15.5(0건) 대비 139건으로 악화되어(`docs/review/review_v1_16.md`) 사용자가 폐기했다. 이 문서는 그 검토 과정에서 새로 밝혀진 정확한 근본 원인(테이퍼 중첩, 회전 아님)을 바탕으로 사용자가 제안한 **완전히 새로운 아키텍처**를 다룬다.

- 근거: `docs/review/review_v1_16.md`(테이퍼 중첩 근본 원인 실측 확인), 사용자 세션 대화(Outer 자신의 좌표만으로 회전 가설을 기각하고 테이퍼 중첩으로 재진단)
- 세션: `/synod idea` (fairy_tail 프로젝트, Gemini flash/thinking-high conf95 — pro는 rate limit으로 flash 폴백 — + OpenAI gpt4o conf85/can_exit=false, Claude 검증·종합)
- 사용자 제안 아키텍처: **① Plate 등 플랜지 고정점의 y좌표를 고정하고, 개별 노드 오프셋/테이퍼를 쓰지 않는다. ② 두께 성장으로 겹침이 생기면 해당 파트 전체를 y축 방향으로만(모든 노드가 완전히 동일한 y-shift로) 평행이동시켜 해소한다.**

## 1. 왜 이 아이디어가 근본 원인을 정확히 겨냥하는가

`review_v1_16.md`가 실측으로 확인한 버그의 정체는 "회전"이 아니라 **테이퍼(taper) 가중치 중첩**이었다. `point_idx 1,2,3`처럼 서로 1칸 떨어진 등록 플랜지 노드들이 각자 자기 몫(가중치 1.0)에 더해 서로의 테이퍼(±1칸=2/3, ±2칸=1/3)까지 겹쳐 받아서, 가운데 노드(2번)는 총 2.33배, 양끝은 2.0배를 받는 **노드별로 다른 배율**이 문제였다. 그 결과 원래 완전히 같은 y였어야 할 플랜지 라인이 학습 후 미세하게 어긋난다.

사용자의 제안은 이 문제의 구조를 정확히 겨냥한다: **"노드마다 다른 배율을 적용하는 메커니즘(테이퍼)" 자체를 없애고, "파트 전체가 항상 완전히 동일한 값만큼 움직이는 메커니즘(강체 y-shift)"으로 교체**하면, 애초에 "노드마다 다른 배율"이라는 개념 자체가 존재하지 않으므로 이 버그가 구조적으로 발생할 수 없다. Gemini(conf95)·OpenAI(conf85) 모두 이 점에 동의했다 — 개별 노드 가중치 누적(bleed)이 원인이었으므로, 파트 단위 공통 변위로 바꾸면 그 누적이 발생할 여지 자체가 없다.

## 2. 구현 시점 — Export 후처리가 아니라 학습(Training-time) 내부로

`v1.16`은 export 시점 후처리(`align_flange_pairs_rigid()`)로 접근했다가 실패했다. 이유는 (a) 학습 중에는 여전히 버그가 있는 테이퍼 메커니즘이 그대로 작동해 형상을 왜곡시키고, (b) export 시점에만 사후 보정을 걸다 보니 학습이 "본" 형상과 최종 export 형상이 달라져 새로운 부작용(Inner-Patch1 상대 위치 이동)을 낳았다.

Gemini·OpenAI 모두 이번 아이디어는 **학습 루프(`forward()`) 내부에서 처음부터 테이퍼를 대체**해야 한다고 권고했다 — export 후처리로는 v1.16과 같은 실패를 반복할 위험이 있다.

- **구체적 위치**: `identify_mating_flange_pairs()`가 만드는 노드별 오프셋·테이퍼 로직(`AI_design_v1_15_5.py` L1287-1329)을 통째로 대체한다. 대신 파트별 스칼라 `Δy_part`를 계산해 그 파트의 **모든 노드**(플랜지 노드든 자유 노드든 구분 없이)에 동일하게 더한다.
- 이렇게 하면 `Δt`(두께 변화)에 따라 미분 가능한 방식으로 `Δy_part`를 계산할 수 있어(예: `Δy_part`가 이웃과의 필요 간극에서 유도되는 닫힌 형태 함수라면) 학습 중 그래디언트가 두께→형상 경로로 계속 흐를 수 있다(v1.15의 원래 설계 의도 보존).

## 3. Plate의 4중 이웃 충돌 — Y-only가 "쉽게 풀린다"는 것은 절반만 맞다 (Judge 정정)

Gemini는 "Y-only는 1차원 선형계이므로 2D보다 안정적으로 유일해를 준다"고 다소 낙관적으로 서술했다. **이것은 절반만 맞다 — 명확히 구분해야 할 두 가지 서로 다른 문제가 있다:**

- **문제 A (테이퍼 중첩, 이번에 확실히 해결됨)**: 같은 파트-쌍 카테고리 내에서 노드마다 다른 배율을 받는 문제. 파트 전체가 하나의 `Δy_part`만 갖게 하면 이 문제는 **정의상 100% 사라진다** — 노드 간 배율 차이라는 개념 자체가 없어지기 때문이다.
- **문제 B (Plate의 4개 이웃이 서로 다른 `Δy_Plate`를 요구하는 경우, 별개의 문제)**: Plate 하나에 대해 Outer·Inner·Patch1·Patch2가 각자 원하는 `Δy_Plate`가 다르면, **Y-only라 해도 4개 방정식에 미지수 1개(`Δy_Plate`)뿐이라 여전히 과결정계(over-determined)**다. 자유도가 2D→1D로 줄어든다고 해서 "4개 요구가 자동으로 일치하게" 되는 것은 아니다 — 단지 남는 잔차가 2D 벡터가 아니라 1D 스칼라가 되어 다루기 쉬워질 뿐이다.

**Judge 판단**: 문제 A(테이퍼 중첩, `review_v1_16.md`의 136/139건 원인)는 이 아이디어로 확실히 해결된다. 문제 B(Plate 다중 이웃, Inner-Patch1 최대 침투 건의 유력한 원인)는 이 아이디어가 "덜 나쁘게" 만들어주지만 **자동으로 완전히 해결하지는 않는다** — 여전히 4개 요구 중 하나를 우선하거나(예: v1.16처럼 Outer를 앵커로 최우선 적용) 최소자승으로 절충하는 정책이 필요하다. 다만 1D 최소자승은 2D보다 계산이 단순하고 해석이 쉬워, v1.16의 2D 평균화보다는 확실히 안정적인 개선이다.

## 4. 두께 성장 자유도가 유지되는가 (v1.15의 원래 문제 재발 여부)

v1.15가 애초에 노드별 오프셋을 도입한 이유는 "양쪽 다 위치 고정된 노드 사이에서 두께가 커지면 기하학적으로 불가능한 제약이 걸려 두께가 부당하게 억눌린다"는 문제 때문이었다(`command_v1_15.md` §0). 플랜지 점의 y좌표를 "고정"한다고 하면 이 문제가 재발하는 것처럼 들리지만, **고정하는 것은 "그 노드 하나만의 개별 오프셋"이지 "파트 전체의 위치"가 아니다** — 두께가 커지면 파트 전체가 `Δy_part`만큼 자동으로 밀려나므로(사용자 제안 ②), 개별 노드 레벨에서는 여전히 압박이 없다. Gemini·OpenAI 둘 다 이 설계가 v1.15의 원래 문제를 재발시키지 않는다는 데 동의했다 — 단, **`Δy_part`가 실제로 "자동으로" 계산되어 매 forward마다 적용돼야** 한다는 조건이 붙는다(사람이 수동으로 트리거하는 방식이 아니라, 두께 변화가 감지되면 즉시 파트 이동으로 반영되는 닫힌 형태 함수여야 함).

## 5. 구현 순서 권고

1. **1단계 — 테이퍼 제거 + 파트 단위 Δy 계산(닫힌 형태)**: `identify_mating_flange_pairs()`/`forward()`의 노드별 오프셋·테이퍼 로직을 제거하고, 각 파트쌍(Outer-Plate, Plate-Inner, Plate-Patch1, Plate-Patch2)에 대해 "그 쌍의 필요 y-거리"를 계산하는 함수로 교체한다. Outer를 앵커(`Δy_Outer=0`)로 고정하고 Plate는 Outer 쪽 요구만으로 우선 결정한다(문제 B의 최소 위험 정책, v1.16의 Outer 우선 원칙을 계승).
2. **2단계 — Plate의 나머지 이웃(Inner/Patch1/Patch2) 처리**: Plate가 확정된 후 각 자식 파트는 자신과 Plate 사이의 필요 y-거리만으로 자기 `Δy_child`를 결정한다(Plate 쪽에서 여러 자식의 요구를 동시에 만족시키려 하지 않음 — 문제 B를 자식 쪽에서 흡수).
3. **3단계 — Inner-Patch2 샌드위치 예외 처리**: 목표 간극이 0이 아니라 `t_Plate`인 샌드위치 관계를 별도 상수/공식으로 유지(기존 `FLANGE_PAIR_SPEC`의 Inner-Patch2 카테고리와 동일한 예외 취급).
4. **4단계 — 검증**: `initial_section_v4.csv`(이미 gap0=0으로 검증된 입력)로 회귀 테스트해 파트 전체가 움직이지 않는지(불필요한 이동 없음) 확인하고, 인위적으로 두께를 늘려 파트가 정확히 필요한 만큼만 y로 밀리는지, Outer-Plate류의 "가운데 노드만 어긋나는" 패턴이 완전히 사라지는지(모든 등록 플랜지 노드가 소수점 단위까지 동일 y를 갖는지) 확인한다.

## 6. 아이디어 순위

### Idea 1 (권장, 1순위): 학습 시 파트 단위 Y-shift로 테이퍼 완전 대체

§2~§5에 기술한 방식. 테이퍼 중첩 버그를 구조적으로 제거하고, v1.16이 실패한 "학습-export 불일치" 문제도 원천적으로 피한다(학습 자체가 이 형상을 보고 최적화하므로 export는 그 결과를 그대로 내보내기만 하면 됨).

- **장점**: 문제 A(136/139건) 완전 해결. 미분 가능하게 구현 가능해 v1.15의 설계 철학(두께→그래디언트 경로 보존) 유지.
- **리스크**: `forward()` 내부 수정이라 v1.15부터 안정적으로 써온 기존 오프셋 로직을 완전히 교체해야 함(리스크 있는 변경). Plate의 다중 이웃(문제 B)은 3단계 정책(Outer 우선)으로 완화되지만 완전 소거는 아님.

### Idea 2 (차선책): Export 시 Y-only 후처리 (v1.16의 교훈으로 기각 권고)

학습은 그대로 두고 export 직후 파트 단위 y-shift만 적용. 구현은 쉽지만, v1.16이 정확히 이 패턴(export 후처리)으로 실패했으므로 **권장하지 않는다** — 두 모델 모두 "차선책, 고위험"으로 분류.
