## 0. 결정적 발견 — 남은 겹침은 "설계 결함"이 아니라 "모델링 아티팩트"다

이번 세션에서 Claude가 실측으로 확인한 사실이며, v1.15 설계 전체의 근거다.

**(1) 초기 형상의 일부 고정 노드쌍은 정확히 "표면 접촉" 상태로 설계되어 있다.**
`initial_section_v2.csv`에서 양쪽 노드가 모두 BC 고정(`fix=1`)인 쌍 중, 중심선 간 거리가
`(t_a + t_b)/2`와 **1e-6mm 이내로 정확히 일치**하는 쌍이 존재한다(용접 플랜지 = 맞닿아야 정상):

| 파트쌍 | 접촉 쌍 수 | 접촉 기준 간격 | 위치 |
|---|---:|---:|---|
| #00(Outer)-#03(Plate) | 6쌍 | 1.950mm = (2.3+1.6)/2 | floor 16, x=0.00 |
| #03(Plate)-#06(Inner) | 6쌍 | 1.600mm = (1.6+1.6)/2 | floor 16, x=33.10 |

**(2) v1.14의 잔여 겹침은 두께 증가분과 정확히 같다.**

| 파트쌍 | 초기 필요간격 | v1.14 필요간격 | 예측 겹침 | **실측 겹침** |
|---|---:|---:|---:|---:|
| Outer-Plate | 1.9500 | 2.0120 | +0.0620 | **0.0620** |
| Plate-Inner | 1.6000 | 2.0119 | +0.4119 | **0.4119** |

소수점 4자리까지 완전히 일치한다. 즉 **겹침 = (변경된 두께합/2) − (초기 두께합/2)** 이며, 원인은
단 하나다: 플랜지는 맞닿도록 설계됐는데 두께가 자라는 동안 중심선이 벌어지지 못했다(양쪽 노드가
BC 고정이라 좌표 자유도 0).

**(3) 따라서 지금까지의 collision loss는 기하학적으로 만족 불가능한 제약을 강요해 왔다.**
이 접합부에서 위반을 줄이는 유일한 경로는 "두께를 도로 줄이는 것"뿐이었고, 이것이 v1.14에서
Plate가 1.72mm, Patch2가 T_MIN(0.7mm)까지 깎인 이유의 상당 부분을 설명한다. Mp 달성률이 78.8%에
머문 것과 직결된다.

## 1. 사용자 제안 (A)·(B)에 대한 판정

### (A) 고정 노드끼리의 상호작용을 collision loss에서 제외 — **타당, 단 단독으로는 불충분**
두 모델 모두 타당하다고 판정했다. 접합 플랜지에서 접촉은 **의도된 설계**이고, 두 노드 모두 고정이라
옵티마이저가 해결할 수도 없으므로, 페널티는 두께를 깎는 헛된 하방 압력만 만든다.

단, **(A)만 적용하면 위반을 손실에서 "숨길" 뿐 실제 형상은 여전히 간섭 상태**다. 두 Critic 모두
진단용 안전장치를 필수로 못박았다(§3-⑥).

### (B) 두께 증가분만큼 서로 밀어내기(절반씩 반대 방향) — **타당하며, 이전 세션 결정에 위배되지 않음**
`idea_v1_14.md`는 "fix 마스크를 완화해 경계 노드를 자유 이동시키는" 안을 조립성/용접성 근거로
**기각**하면서, "접합 쌍이 동일 변위 벡터로 함께 움직이는 공동 이동 제약(rigid-body coupled
displacement)"이라는 훨씬 좁은 형태만 후속 검토 대상으로 남겼다.

제안 (B)는 **정확히 그 허용된 좁은 변형**이다 — 두 모델 모두 독립적으로 같은 결론에 도달했다:
- **결정론적**: 학습되는 자유 변수가 아니라 두께의 함수로 일의적으로 결정된다.
- **대칭적**: 절반씩 반대로 움직이므로 **접합 계면(두 중심선의 중점)이 보존**된다.
- **CAD 표준**: 판재 두께 변화 시 중립면(mid-surface) 오프셋과 동일한 처리다.

즉 "플랜지 정렬이 깨져 제조 불가 형상이 된다"는 기각 사유가 (B)에는 해당하지 않는다.

## 2. 타이밍 3안 비교 — **Option 3 채택**

| | Option 1 (전 구간 상시) | Option 2 (Stage3→4 1회) | **Option 3 (미분 가능 오프셋 레이어)** |
|---|---|---|---|
| 방식 | 매 스텝 좌표에 비미분 투영 | epoch 500에 1회 좌표 보정 | `forward()` 안에서 두께의 함수로 공식화 |
| 장점 | 학습 내내 간섭 방지 | 구현 단순 | **두께→좌표→Mp 그래디언트 일관성 유지** |
| 단점 | 투영이 옵티마이저와 싸움, 진동 위험 | **Stage4 200epoch가 겹침을 재발시킴** | 구현 복잡도 ↑ |
| 판정 | 비추천 | 비추천 | **채택** |

두 모델 모두 Option 1/2를 기각하고 Option 3으로 수렴했다. 특히 Option 2의 치명적 약점은 명확하다 —
Stage4는 좌표와 두께를 200epoch 동안 다시 최적화하므로, 1회 보정은 곧바로 무효화된다.

**Option 3 정의**: 초기 형상에서 접합 쌍과 단위 법선을 1회 사전 계산해 버퍼로 캐싱하고,
`CGDN17.forward()`에서 **BC 마스크 적용 이후에** 두께 함수인 오프셋을 더한다.

```
x_i = x_i,init + delta_i(BC 적용) - 0.5 * Δt_a * n_ij
x_j = x_j,init + delta_j(BC 적용) + 0.5 * Δt_b * n_ij
```

이렇게 하면 두께 증가가 좌표 팽창으로 미분 가능하게 전달되어, **Mp가 "두꺼워지면 단면이 커진다"는
실제 물리를 올바르게 반영**한다. Mp 상승은 공짜 보너스가 아니라 물리적으로 정당한 거동이며,
autograd 안에 있으므로 목적함수 왜곡이나 이중계상이 아니다(양 모델 공통 판정).

## 3. 반드시 함께 반영해야 할 6개 쟁점 (Critic 라운드 판정)

### ① 다중 pair 노드 — **실재하는 문제 (Judge가 실측으로 판정)**
Gemini Critic은 "접촉 노드가 서로 다른 point_idx라 샌드위치 노드는 없다"며 과잉설계로 기각했으나,
**이는 ④의 일반화를 채택하는 순간 성립하지 않는다**. Claude 실측 결과:

> 일반화 규칙(모든 fixed-fixed 쌍) 적용 시 pair 408개, 관여 노드 663개 중
> **153개(23%)가 2개 이상의 pair에 동시에 관여**한다.

Gemini Critic이 ④(일반화)를 "필수"로 채택하면서 ①을 기각한 것은 **내부 모순**이다. OpenAI Critic이
지적한 중첩 누적 위험이 이 조건에서는 유효하다.

**권고**: `index_add_`(합산)로 시작하되, **pair별 잔여 위반량을 진단 지표로 로깅**한다. 잔여가
무시할 수 없으면 접촉 컬럼 단위 1D 체인 최소제곱 분배로 격상한다(단계적 접근 — 처음부터 체인
솔버를 넣는 것은 과잉).

### ② Kink 재발 위험 — **최대 리스크, taper 필수 (양 모델 공통·강력)**
플랜지 고정 노드만 최대 0.206mm 밀고 바로 옆 자유 노드는 그대로 두면 폴리라인에 단차가 생긴다.
이 프로젝트는 v1.7~v1.10 **네 개 버전에 걸쳐 바로 이 "국소 꺾임/스파이크" 문제와 싸웠다**
(`compute_smoothness_lse_v3`, boundary continuity loss, Top-K smoothness). 그 결함을 다시 만드는
것은 용납할 수 없다.

**권고**: 플랜지 경계에서 자유 영역 쪽으로 **N개 이웃(N=2~3)에 걸쳐 오프셋을 1.0→0.0으로 테이퍼**
(선형 또는 코사인)한다. 정적 이웃 맵은 이미 `build_static_neighbor_map()`으로 존재하므로 재사용한다.

### ③ 오프셋을 구동하는 두께 — **`t_raw` 사용 + pair 단위 존재 게이팅 (Judge 종합)**
- Gemini Critic: `t_final`(= t_raw × z_gate)을 써야 한다 — 삭제된 파트는 밀어낼 이유가 없다.
- OpenAI Critic: `t_raw`를 써야 한다 — 게이트는 제조 의사결정일 뿐 기하/용접 관계가 아니다.

**Judge 판정**: **`t_raw`가 맞다.** 학습 중 `z_gate`는 0~1의 **연속 완화값(존재 확률)**이지 물리적
두께가 아니다. `t_final`을 쓰면 게이트가 0.5일 때 "두께가 절반인 판재"라는 실재하지 않는 기하가
만들어진다. 다만 Gemini의 우려도 유효하므로, **파트가 hard 삭제된 경우 그 pair 전체를 비활성화**하는
방식으로 해소한다(두께를 흐리는 것이 아니라 pair를 끄는 것). 두 입장의 실패 모드를 모두 회피한다.

> 참고: OpenAI Critic이 제안한 `with torch.no_grad(): t_eff = t_raw` 디태치는 **채택하지 않는다** —
> 두께→좌표→Mp 그래디언트 경로가 Option 3의 존재 이유인데 그것을 끊어버린다. 학습이 불안정할 때의
> 최후 폴백으로만 기록해 둔다.

### ④ 접촉 쌍 한정 vs 초기 간극 보존 — **일반화 채택 (양 모델 공통)**
정확 접촉 쌍은 12개(floor 16)뿐인데 v1.14 겹침은 floor 10~16에 걸쳐 있었다. floor 10~15는 초기
간극이 작지만 0이 아니었고 두께 성장이 그걸 잠식한 경우다. 따라서 "접촉 복원"만으로는 부족하다.

**채택 규칙 — 초기 표면 간극 보존**:
```
gap0_ij = dist0_ij - (t_a,init + t_b,init)/2      # 설정 시 1회 캐싱
목표: dist_ij - (t_a + t_b)/2 == gap0_ij         # 매 forward에서 유지
```
`gap0 = 0`이면 접촉 유지 케이스로 자연스럽게 축소되므로 수학적으로 일관된다.

### ⑤ Autograd 구현 결함 — **벡터화 필수 (양 모델 공통)**
Solver 라운드의 의사코드(`for pair in mating_pairs: offset_coords[i] -= ...`)는 grad를 가진 텐서에
대한 **in-place 인덱스 쓰기**를 pair마다 반복하므로 autograd 오류/중복 쓰기/성능 저하를 유발한다.

**권고**: 설정 시 1회 `register_buffer`로 인덱스·법선·부호 텐서를 만들고, forward에서는
```python
offsets = torch.zeros_like(coords)
offsets.index_add_(0, idx_a, -0.5 * dt_a.unsqueeze(-1) * normals)
offsets.index_add_(0, idx_b, +0.5 * dt_b.unsqueeze(-1) * normals)
new_coords = coords + offsets
```
`build_collision_spec()`이 이미 쓰는 "초기 형상에서 1회 산정" 패턴을 그대로 따른다.

### ⑥ (A)가 실제 위반을 은폐할 위험 — **이중 안전장치 필수 (양 모델 공통)**
**권고**: (i) 마스킹하지 않은 **진단 전용 관통 지표**를 `detach()` 상태로 매 epoch 로깅(역전파 없음),
(ii) `export_final_section_csv()` 직후 **하드 assert**(허용 오차 예: 0.01mm 초과 시 중단).
오프셋 레이어가 빠지거나 잘못 설정돼도 조용히 통과하지 못하게 한다.

### ⑦ (추가) 법선 벡터 고정 문제 — Gemini Critic 지적
초기 형상에서 법선을 1회 고정하면 형상이 변형될 때 방향 불일치가 생길 수 있다. 다만 대상이 BC 고정
노드 주변이라 변형이 작으므로, **1차 구현은 정적 법선으로 시작**하고 검증에서 각도 편차를 측정해
필요 시 동적 갱신으로 격상한다.

3. **[필수] 테이퍼링** — 플랜지 경계에서 이웃 N=2~3개까지 오프셋 감쇄(②). v1.7~v1.10 스파이크
   재발 방지의 핵심.
4. **[필수] collision loss 마스킹** — `compute_collision_loss_v5()`에서 fixed-fixed 쌍에 해당하는
   (segment, point) 항목 제외(A). 리터럴 graph edge가 아니라 **투영 항목 마스킹**임에 주의.
5. **[필수] 이중 안전장치** — 진단 전용 비마스킹 관통 지표 로깅 + export 후 하드 assert(⑥).
6. **[검증]** 다음을 확인한다:
   - 학습 중 플랜지 쌍의 `dist - (t_a+t_b)/2`가 `gap0`를 유지하는가(오차 1e-4mm 이하)
   - 다중 pair 노드(153개)의 잔여 위반량 — 무시 가능한가, 체인 솔버로 격상이 필요한가(①)
   - 스무딩 손실(`l_smooth_lse`)이 v1.14 대비 악화되지 않는가(② taper 효과)
   - Mp 달성률이 78.8%에서 개선되는가(두께 하방 압력 해소 효과)
   - 최종 CSV 겹침 = 0
