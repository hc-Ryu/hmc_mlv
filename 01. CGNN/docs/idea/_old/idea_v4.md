## 2. 제안 A — `l_sparse` 제거 (Req 4의 본질적 해법)

### A.1 코드로 검증된 사실

**미분 가능한 질량 목적함수가 이미 존재한다.**

`AI_design_v1_2.py:1024`
```python
area, l_mass = usv18.compute_mass_loss(new_coords, t_final, edge_index, edge_attr, target_area)
```

`uni_section_v18.py:476-490`
```python
def compute_mass_loss(new_coords, t, edge_index, edge_attr, target_area):
    seg_len = torch.norm(new_coords[src] - new_coords[dst], dim=1)
    t_src   = t[src].squeeze(-1)
    area    = torch.sum(seg_len * t_src)          # ← 미분 가능
    l_mass  = torch.relu(area / target_area - 1.0) ** 2
    return area, l_mass
```

여기 들어가는 `t`는 `t_final = t_raw * z_gate` (`AI_design_v1_2.py:246`)이다.
따라서 **면적은 이미 게이트에 대해 미분 가능**하고, ALDA를 통해 `f = area / target_area`로
손실에 직접 들어간다 (`uni_section_v18.py:496, 506`).

> ### ⚠️ 정정 ① (2026-08-08) — 위 코드 블록의 `l_mass`는 손실이 아니다
>
> 위 인용은 `compute_mass_loss()`를 전면에 배치해 **`l_mass`가 질량 목적함수인 듯한 인상**을 준다.
> 코드 확인 결과 **`l_mass`는 계산·로깅만 되고 `loss`에 더해지지 않는다.**
>
> ```python
> :1024  area, l_mass = usv18.compute_mass_loss(...)
> :1048  loss = (contrib_phys + contrib_smooth + L_alda_effective
>                + contrib_order + contrib_anchor + contrib_sat
>                + contrib_sparse + contrib_entropy + contrib_continuity)   # ← l_mass 없음
> :1071  "l_mass": l_mass.item(),      # 로깅 전용
> ```
>
> **본문의 "ALDA를 통해 `f = area/target_area`로 손실에 직접 들어간다"는 서술이 정확하며,
> 제안 A의 근거는 그것 하나로 충분하다.** `l_mass`는 근거가 아니다.
>
> 이 혼동 때문에 `command_v1_3.md` 초안이 ALDA 문장을 떨어뜨리고 `l_mass`만 근거로 인용하는
> 오류를 범했다. 파생 문서를 쓸 때는 **`f`를 명시**할 것.
>
> **[후속]** `command_v1_3.md` §2.6에서 `l_mass`를 **감량 목표(95%)의 예산 제약**으로
> `loss`에 편입한다. v1.3의 의도적 신규 변경이며, v1_2 시점의 위 사실과는 별개다.

> ⚠️ **혼동 주의**: `compute_section_area()` (`uni_section_v18.py:934-953`)는 `torch.no_grad()`로
> 감싸여 있고 `.item()`을 반환한다. 이것은 **리포팅 전용 지표**이며 손실이 아니다.
> 두 함수를 구분하지 못하면 "면적은 미분 불가능하니 counterfactual 모델이 필요하다"는
> 잘못된 결론에 도달한다 (Solver 라운드에서 실제로 발생한 오해).

### A.2 그래서 `l_sparse`는 무엇을 하고 있나

`uni_section_v18.py:1074`
```python
l_sparse = z_open[CANDIDATE_PARTS].mean()      # 게이트 "개수"를 셈. 질량과 무관.
```
`uni_section_v18.py:658` — `W_SPARSE = 0.5` (주석: "기존 0.05 → 상향", **10배**)

게이트 하나를 내릴 때의 손실 그래디언트를 분해하면:

```
∂L/∂z_k = A_k(t_k) / target_area          ← 실제로 절약되는 물리적 면적 (f 항)
        + w_sparse · gate_mult / (17·n_cand)   ← 인공 페널티 (파트 크기와 무관)
        - λ·(∂Mp/∂z_k)·…                  ← Mp 손실을 메우려는 보상 압력
```

> ### ⚠️ 정정 ④ (2026-08-08) — 단위를 맞추지 않으면 결론이 정반대로 읽힌다
>
> 초판은 첫 항을 `A_k`로만 적었다. `f = area / target_area`이므로 **`target_area`로 나눠야** 하고,
> 둘째 항도 `l_sparse = z_open[:, CAND].mean()`의 평균 연산 때문에 게이트 수로 나뉜다.
> 정규화 없이 비교하면 `A_k`(≈200)가 `w_sparse`(0.5)보다 훨씬 커 보여 **제안 A의 논거가
> 거꾸로 읽힌다.** 실제 값은 다음과 같다.

| 항 | 게이트 1개당 그래디언트 |
|---|---|
| 물리 면적 (`f`) | `A_k / target_area` ≈ 200 / 24,057 ≈ **0.0083** |
| `l_sparse` (현행) | `0.5 · gate_mult / (17 × 2)` ≈ **0.0147**·gate_mult |

`w_sparse`가 **면적과 무관한 상수**이므로, 면적 기여가 작은 패치일수록
`w_sparse ≫ A_k/target_area`가 되어 **물리적으로 이득이 없어도 삭제가 강제된다.**
위 수치에서 인공 페널티가 물리 신호를 **약 1.8배 압도**한다.
그 결과 Mp를 맞추기 위해 17개 섹션 전체에 걸친 연속 파트가 두꺼워지고,
연속 파트는 기저 면적이 훨씬 크므로 **순 질량은 증가한다.** 이것이 +10.1%의 메커니즘이다.

### A.3 수정안

**A안 (권장): `l_sparse` 완전 제거**
```python
# uni_section_v18.py:1074-1075 — 삭제 또는 W_SPARSE = 0.0
# contrib_sparse = 0
```
면적 항이 유일한 질량 심판이 된다. "이 파트를 지우면 실제로 질량이 주는가?"라는
counterfactual을 **그래디언트가 정확히 계산**한다. 별도 예측 모델도, rollback 상태 기계도 필요 없다.

**B안 (보수적): 면적 가중 `l_sparse`**
```python
# 각 게이트를 자기 파트의 실제 면적 기여로 가중
with torch.no_grad():
    a_k = per_candidate_edge_area(new_coords, t_raw, ...)   # (17, n_cand)
    a_k = a_k / (a_k.sum() + 1e-9)
l_sparse = (z_open[:, CAND] * a_k).sum()
```
플랫 페널티의 왜곡은 없애면서 희소화 방향성은 유지한다.

### A.4 기각된 대안 — rollback 상태 기계

Solver 라운드에서 "PENDING_DELETE 20 epoch 창에서 질량 스냅샷을 비교해 삭제를 취소한다"는
안이 제시되었으나, **Critic·Defense 양쪽에서 모두 기각**되었다.

- PENDING 진입 시점에는 이미 게이트가 억제(<0.08)되어 연속 파트가 **이미 두꺼워진 뒤**다.
  epoch t와 t+20의 질량 비교는 counterfactual이 아니라 옵티마이저 궤적의 합산일 뿐이다.
- 롤백해도 두꺼워진 연속 파트와 옵티마이저 모멘텀은 원복되지 않는다 → 이력현상(hysteresis).
- "삭제 → 보상 → 롤백 → 재삭제" 무한 루프 위험. 억제 기간 하이퍼파라미터가 새로 필요.

## 3. 제안 B — 이진화/프루닝 임계 정렬 (Req 3)

### B.1 "조용한 죽음의 구간(Silent Death Zone)"

현재 두 임계값이 **정렬되어 있지 않다**:

| 역할 | 값 | 위치 |
|---|---|---|
| 비가역 프루닝 트리거 | `ewma_z < 0.08` | `uni_section_v18.py:228` |
| 최종 이진화 컷 | `z_gate > 0.5` | `AI_design_v1_2.py:721` |

구간 **[0.08, 0.5]**에 있는 게이트는 프루닝되지 않아 학습 내내 **하중을 분담하는 것으로 취급**되지만,
최종 이진화에서 **조용히 삭제**된다. 학습이 최적화한 구조와 제조되는 구조가 달라진다.

섹션 10·11·12의 Patch1이 정확히 이 구간에 있었다(state=ALIVE, `z_gate < 0.5`).
**이것이 섹션 11 강성 미달(95.0%)의 직접 원인이다.**

### B.2 요구 3의 진짜 정당화

임계값 0.3은 "안전 여유"가 아니라 **죽음의 구간 축소**로 정당화된다:

```
현재:   [0.08, 0.5]  폭 0.42
Req 3:  [0.08, 0.3]  폭 0.22   ← 병리 절반으로 감소
이상적: 폭 0          ← 두 임계 완전 정렬
```

이렇게 보면 요구 3과 요구 4는 **충돌하지 않는다.** 요구 3은 "질량을 늘리자"가 아니라
"학습이 쓴다고 가정한 재료를 사후에 몰래 뺏지 말자"이다. 뺏은 재료는 어차피 Mp 미달로 되돌아온다.

### B.3 수정안

```python
# AI_design_v1_2.py — 모듈 상단
BINARIZE_THRESHOLD = 0.3      # Req 3. 이상적으로는 프루닝 임계와 정렬

# report_design_comparison() :721
exists_full = (state != DELETED) & (z_gate > BINARIZE_THRESHOLD)
```

### B.4 ⚠️ 반드시 알아야 할 한계

`exists = (state != DELETED) AND (z_gate > threshold)`이므로,
**이미 `DELETED` 확정된 것은 임계값을 아무리 낮춰도 되살아나지 않는다.**

현재 실행 기준으로 임계 0.3의 효과 범위:
- Patch1 섹션 0~9: `DELETED` 확정 → **효과 없음**
- Patch2 전 섹션: `DELETED` 확정 → **효과 없음**
- **Patch1 섹션 10·11·12: state=ALIVE → 여기에만 효과 있음**

즉 임계값 변경만으로는 섹션 11 정도만 구제된다. 기대치를 여기에 맞춰야 한다.

## 4. 제안 C — 이진화 압력은 `W_SPARSE`가 아니라 `ALPHA_ENT`로 (신규 제안)

세션 중 발견된 사항으로, 요구사항에는 없지만 **게이트 미수렴 문제의 직접적 해법**이다.

### C.1 온도 어닐링은 `z_gate`를 이진화하지 못한다

`uni_section_v18.py:197-206`
```python
z_gate = torch.clamp(sigmoid(log_alpha) * (zeta - gamma) + gamma, 0.0, 1.0)   # temperature 없음
z_open = torch.clamp(sigmoid((log_alpha + noise) / temperature) * ... )        # temperature 사용
```
`z_gate`는 **온도와 무관**하다. 게다가 `TEMP_WARMUP_EPOCHS = 30`(`:673`)이라 온도 어닐링은
epoch 41쯤 이미 끝난다. 1500 epoch 실행에서 온도는 사실상 상수였다.

`z_gate`는 `γ=-0.1, ζ=1.1`의 stretched sigmoid이므로 `|log_alpha| > 2.4`에서 **정확히 0/1로 포화**한다.
포화시키는 유일한 방법은 `log_alpha`를 밀어내는 것뿐이다.

### C.2 `W_SPARSE`는 단방향, `ALPHA_ENT`는 대칭

| 항 | 값 | 방향 |
|---|---|---|
| `W_SPARSE` | **0.5** (`:658`) | **아래로만** — 삭제 편향, 이진화 아님 |
| `ALPHA_ENT` | **0.01** (`:662`) | **양방향** — 0 또는 1로 밀어냄 |

`uni_section_v18.py:1080-1082`
```python
entropy = -mean(z·log z + (1-z)·log(1-z))
contrib_entropy = (ALPHA_ENT * gate_multiplier) * entropy   # loss에 (+)로 가산
```
손실에 양수로 더해지므로 **엔트로피를 최소화** = z를 0 또는 1로 민다. 이것이 진짜 이진화 압력이다.
그런데 가중치가 `W_SPARSE`의 **1/50**에 불과하다.

### C.3 수정안

```python
W_SPARSE  = 0.0 ~ 0.05    # 제안 A와 함께 대폭 축소 (현재 0.5)
ALPHA_ENT = 0.05 ~ 0.1    # 이진화 압력 이관 (현재 0.01)
```
> "게이트가 안 수렴하니 `W_SPARSE`를 올리자"는 **틀린 처방**이다. Patch2가 전멸한 것처럼
> 남은 패치도 지워질 뿐이다. 이진화를 원하면 `ALPHA_ENT`를 올려야 한다.

## 7. 상호작용 및 적용 순서

```
[1단계] 제안 A + C 적용  (W_SPARSE 0.5→0, ALPHA_ENT 0.01→0.05)
        └ 재학습 → 면적이 실제로 감소하는지, 게이트가 포화(|log_alpha|>2.4)하는지 확인
                   ↓
[2단계] 제안 D 적용  (T_MIN 0.7 / T_MAX 2.3 + assert)
        └ 재학습 → Outer Hat이 상한에 붙는지, 좌표가 그 부담을 흡수하는지 확인
                   ↓
[3단계] 제안 B 적용  (BINARIZE_THRESHOLD 0.3)
        └ 리포트에서 죽음의 구간에 남은 게이트 수 확인
                   ↓
[4단계] 그래도 애매한 게이트가 남으면 제안 E (Stage 4) 추가
```

> **[정정 ② 반영]** 4단계의 Stage 4는 **연속 부재 두께 pooling 완화 없이** 수행된다.
> 게이트를 0/1로 확정한 뒤 **좌표 + 전 파트 두께(연속 부재 포함, 단일 변수)** 를
> `[0.7, 2.3]` 범위에서 재수렴시키는 것이 전부다. 상세는 `command_v1_3.md` §5.

**요구 3 vs 요구 4는 충돌하지 않는다** — 제안 B.2에서 설명한 대로, 요구 3은 질량을 늘리는 것이

## 9. 미검증 가정 (그대로 믿지 말 것)

숙의 과정에서 제기되었으나 **코드/데이터로 확인되지 않은** 주장들:

1. **"섹션 11의 게이트는 0.15였다"** — Defense 라운드에서 나온 구체적 수치이나 **근거 없음**.
   실측은 Patch1 생존 7개 섹션의 **평균 0.584**뿐이고, 섹션별 개별 값은 로그에 없다.
   섹션 10·11·12가 0.5 미만이라는 것만 존재 맵에서 역산된다.
2. **"좌표가 `max_displacement`에 걸려 그래디언트가 0이다"** — `max_displacement = 50.0mm`로
   상당히 넉넉하다. 실제로 클램핑에 걸렸는지는 **측정해 봐야 안다.**
3. **제안 A만으로 게이트가 자연 수렴한다** — 논리적으로 타당하나 실행으로 확인되지 않았다.
   1단계 재학습의 관찰 대상이다.
4. **[신규 2026-08-08] ALDA dual ascent가 동작한다는 전제** — **거짓.** `mu_Mp`/`rho_Mp`를
   갱신하는 코드는 `usv18.run_training()` 안에만 있고 `AI_design_v1_2.py`는 이를 호출하지 않는다
   (자체 `run_training_multi()` 사용). 따라서 실행 내내 `mu_Mp = 1.0`, `rho_Mp = 200.0` 고정이며
   ALDA는 **이름과 달리 고정계수 penalty**로 동작한다.
   - 긍정적 귀결: `mu`가 폭주해 면적 항 `f`를 압도하는 시나리오는 발생하지 않는다.
   - `f`의 계수(1.0)와 Mp 항의 균형이 적절한지는 1단계 재학습의 관찰 대상이다
     (`command_v1_3.md` §2.5).
5. **[신규 2026-08-08] 제안 D의 도달 범위 수치** — `command_v1_3.md` §3.2 표는 `delta = ±DELTA_SCALE`을
   가정한 **정적 상한**이다. 실제로는 `thickness_gate = sigmoid(0.6·(epoch−128))` 승수와
   그룹 평균 pooling이 더 곱해지므로, 표의 범위는 **epoch ≳ 150 이후 & 그룹 내 노드가 함께
   포화할 때**에만 유효하다.
