## 아이디어 평가

### 1. Huber형 충돌 페널티 상한 복원 (최우선, P0)

**설계**: `compute_collision_penalty_unclamped()`의 제곱 항을 δ 경계 기준 Huber loss로 교체.

```
L_col_aux(d) = 0.5 * d^2                  (d <= δ)
             = δ * (d - 0.5*δ)            (d > δ)
```

- **δ = 1.2mm** — 메시/격자 해상도(약 0.5mm) × 2배 안전 배수 + 0.2mm 수치 오차 마진으로 산정한
  값이다. 단, 이 산정 로직은 이번 숙의 세션에서 방어 논리로 구성된 추정치이므로, **v1.5 구현 전
  실제 코드베이스의 메시 해상도 값을 확인해 δ를 재검증**해야 한다(review의 1.0~1.2mm 제안 범위
  내에서 조정 가능).
- **장점**: 관통 10mm에서 페널티가 84.64→56.4로 억제되어(×W_COL_AUX=5.0 기준 423.2→282 수준)
  그래디언트 폭발을 차단한다. 1차 미분(C¹)이 δ에서 연속이므로 경계에서의 인위적 진동이 없다.
- **검증된 반론**: "Huber는 C¹은 연속이나 C²(2차 미분)가 불연속이라 Adam 같은 2차 모멘텀
  옵티마이저에서 불안정할 수 있다"는 우려가 제기됐으나, **Adam은 Hessian이 아니라 그래디언트
  제곱의 지수이동평균(v_t)을 쓰므로 C¹ 연속성만으로 충분히 안정적**이다(Judge 판정: 이 쟁점은
  기각). C² 불연속은 L-BFGS 등 이차 뉴턴법 계열에서만 문제가 되며 본 시스템과 무관하다.
- **실현 난이도**: 하 — `torch.where`로 즉시 구현 가능.

### 2. W_COL_AUX 코사인 웜업 스케줄 + 무방비 구간 방지 floor (최우선, P0)

**설계**:
```
W_COL_AUX(t) = W_floor                                          (t < 50)
             = W_floor + (W_max - W_floor) * 0.5*(1-cos(pi*(t-50)/100))   (50 <= t <= 150)
             = W_max                                             (t > 150)
```

- `W_max = 5.0`, 구간은 §4 지연 엔트로피 활성화 구간(epoch 50~150)과 동기화.
- **v1.4 대비 추가된 안전장치**: 원래 제안(0→5.0)은 웜업 초반(epoch 60~90) 구간에 충돌 페널티가
  거의 0이 되어 관통이 사실상 무방비로 방치된다는 지적이 Defense/Prosecution 심리에서 나왔다.
  콘솔 로깅만으로는 "관측"은 되지만 "억제"는 되지 않는다는 지적은 타당하므로, **`W_floor`를
  0이 아닌 작은 상수(예 0.5)로 설정**해 완전 무방비 구간을 없앤다. 코사인 웜업의 핵심 목적
  (§4의 자유 탐색 공간 확보)은 훼손하지 않으면서 값싸게 리스크를 해소하는 절충안이다.
- **기각된 대안**: 웜업 구간을 50~100으로 단축하고 기울기를 완만하게 하자는 제안은 자기모순적
  (단축과 완만화는 상충)이라 채택하지 않는다.
- **실현 난이도**: 하 — epoch 기반 단순 스케줄러.

### 3. 콘솔 로깅 개선 (P1)

`l_col_aux`와 현재 `W_COL_AUX(t)` 값을 매 epoch 콘솔 출력에 추가:
```
Epoch 100 | Loss: 2.34 | L_col_aux: 0.12 (W: 2.50) | Area: 21200 | Gates_mid: 34
```
목적: (a) 원 리뷰가 지적한 관측 공백 해소, (b) 웜업 스케줄 자체의 버그(오프바이원, 기준 시점
오류)를 다음 실행에서 즉시 검증 가능하게 함. 실현 난이도 하.

### 4. R3 임계값은 절대 불변 (최후순위, P3)

Round 1 Solver 단계에서 Gemini가 "웜업 기간 중 R3 유예(Grace Period)"를 P2로 제안했으나,
Critic 라운드에서 review 원문의 "근본 수정 후 재발 관찰 전까지 R3 불변" 가이드라인과 정면
충돌한다는 지적을 받았고, Defense 라운드에서 제안자 스스로 철회했다. **최종 결론: v1.5에서는
R3를 전혀 건드리지 않는다.** 위 1~3 수정 후에도 R3가 재발하면, 그 시점에야 §7 완화 사다리
(ALPHA_ENT_V13 하향)를 검토한다. 지금 R3를 손대는 것은 실험 변수 통제를 깨고 원인 규명을
불가능하게 만드는 대증요법이다.

**시도하지 말 것**: R3 유예 기간/임계값 조정(근본 수정 전), §4(중립 초기화+지연 엔트로피)
스케줄 되돌리기 — 두 항목 모두 review와 이번 숙의에서 명시적으로 기각됨.

## 우선순위 요약

| 순위 | 항목 | 난이도 | 근거 |
|------|------|--------|------|
| P0 | Huber 충돌 페널티(δ=1.2mm, 실측 후 재검증) | 하 | 그래디언트 폭발 원천 차단 |
| P0 | W_COL_AUX 코사인 웜업 + floor(0.5) | 하 | 공진 방지 + 무방비 구간 리스크 해소 |
| P1 | l_col_aux, W_COL_AUX(t) 로깅 | 하 | 재발 시 즉시 원인 특정 |
| P3 | R3 불변 유지 | - | 근본 수정 후 재발 관찰까지 보류 |

**신뢰도: 89%** (Gemini 최종 95, OpenAI 최종 70/85, Claude 88 — Trust-Score 가중 평균).
핵심 원인(무클램프 페널티) 및 그 해법(Huber+웜업)에는 전 라운드 전 모델이 일치했고, R3 유예
제안은 심리 과정에서 자체 정정됐다는 점에서 견고한 합의로 판단한다.
